# 20261124 停車の緩減速を 0.2G の PI にする

**状態: クローズ（2026-11-26。段5 の非常停止の実機確認はユーザーが OK と判断し、main へマージ）**

非常停止・学習の終わり・自動運転の終わりの停車は、どれも 0.5 mm 踏んでは 1 秒待つ刻み方式で、最大 0.11〜0.13G しか出ていない（0.2G に届かない）。0.2G を目標にした PI に替える。車速が読めないときの刻みは今のまま残し、途中で車速が戻ったら PI へ切り替える。

## 問題

- 非常停止の実機確認（`docs/Phase/RPD_Phase_20261119_EmergencyStop.md` 5 章、2026-11-24）の C（走行中にスイッチ）と D（走行中に AC 断）で、止まるまでの減速が 0.2G に届かなかった。
- 仕様（ユーザー、2026-11-24）: 車速が読めるときは 0.2G の PI で止める。0.5 mm 踏んでは 1 秒待つのは、車速が読めないときだけ。刻んでいる途中で車速が読めるようになったら、0.2G の減速に切り替える。
- 困ること: 高速で非常停止すると、止まるまでが長い。0.2G（7.06 km/h/s）なら 100 km/h から 14 秒で止まるが、今の刻み方式では 30 秒を超える見込み。

## ユーザー決定（2026-11-24）

- 非常停止で車速が読めるときは、0.2G を目標にした PI で止めるのが正しい挙動。
- 範囲は案 b。同じ関数を使う 4 つの場面（非常停止・中断／走行終了ボタン・学習運転を走り終えたとき・自動運転を走り終えたとき）とも PI にする（2026-11-24 に場面の確認のうえ承認）。
- PI の作り（Claude の案をそのまま採用）:
  - 踏み始めは、効き始め（pkl の `brake_onset_u_pct`。無ければ待機位置の min）まで最高速度で一気に動かし、そこから PI を始める。
  - 減速度は 0.1 s の差分を使わず、直近 0.5 s の車速を直線で近似した傾きで測る（窓の長さは仮の値）。
  - P・I の強さはこの車に合わせた固定値にしない。表の「1% 踏んだら何 G 増えるか」（局所の効き）で割る。表が無ければ、いちばん弱い既定値にする。
  - 開度の上限は最大開度。0.3G を超えたら戻す。この 2 つの枠は残す。
- 車速が読めないときは、今の刻み（20 s で max）のまま。刻みの途中で車速を読み直すところを足す。
- 車速が戻ったと判断する条件: 0.5 秒続けて読めたら戻ったとみなし、そのときの開度から PI を始める。戻った時点で止まっていれば（0.2 km/h 以下）、PI を飛ばして N へ。PI の途中で読めなくなったら、そのときの開度から刻みに戻る。
- 確認はスタブまで Claude が行う。実機確認はユーザーが行う。

## 各段の内容

### 段1: `tests/research/stop_decel.py` を 0.2G の PI に替える

**内容**

- `decelerate_to_stop` の刻みのループを、0.1 s 周期の PI に置き換える。
  - 接近: アクセルを原点へ。ブレーキを、効き始め（min + `brake_onset_u_pct`）まで最高速度で動かす。表が無い・効き始めが無いときは min。すでに深く踏んでいれば、その位置（最大開度まで）から始める。
  - PI: 誤差 = 目標 0.2G − 測った減速度。開度 = 接近の開度 + P × 誤差 + I × 誤差の積分。
  - 減速度: 直近 `slope_window_s`（0.5 s）の車速の最小二乗の傾き（今の `decel_from_slope` を使う）。
  - P・I の強さ: 「P だけで誤差の何割を埋めるか」を開度に直す。表の局所の効き（G/%）で割って求める。表が無いときは、いちばん弱い既定値を使う。
  - 枠: 開度は「接近の開度」〜「最大開度」に収める。0.3G（`release_above_g`）を超えたら I を止めて戻す。積分が溜まりすぎないようにする（開度が枠に当たっている間は積分を止める）。
  - 停車（`VEHICLE_STOP_SPEED_KMH` 未満）で抜け、今と同じく停車保持開度まで刻む。`timeout_s` も今のまま。
- 表（pkl の meta）を受け取れるようにする。今は `VehicleProfile` しか受け取っていない。呼び出し元は、表が手に入る所では渡し、無い所では渡さない（既定値で動く）。
- `config` の `decel_stop` に PI のキーを足す。使わなくなるキー（`step_mm`・`dwell_s`・`press_margin_g`・`approach_margin_pct`）は、停車保持への刻みに使うもの以外は外す。`config/robot_common.yaml` と `tests/research/config_*.yaml` もそろえる（[[feedback-settings-must-match-decisions]]・[[research-config-tests-pin-yaml]]）。
- 単体テスト（`tests/research/test_research_stop_decel.py`）を、PI の作りに合わせて書き直す: 効き始めへの接近・0.2G に近づく・0.3G 超えで戻す・最大開度で頭打ち・表が無いときの既定値・停車で抜ける・タイムアウト。

**結果（2026-11-24）**

- `stop_decel.py` を PI に置き換えた。接近 → PI（0.1 s 周期）→ 停車で抜けて停車保持開度まで刻む、の順。
  - 接近: アクセル原点 → ブレーキを min ＋ 表の meta `brake_onset_u_pct`（表・値が無ければ min）へ最高速度で。すでに深ければその位置から。引数 `start_pulse` を渡すと、ブレーキ位置を読まずにその開度から始める（接近を飛ばす）。
  - 表は引数 `table`（ForwardTable。`.meta` と `.accel` を使う）で受ける。無くても動く。表を持たない呼び出し元用に `load_brake_table(cfg)`（FF モデルの pkl を読む。読めなければ None）を足した。
  - 局所の効き k [G/%] ＝ 表の減速度の開度方向の傾き × meta `local_gain_brake` の倍率（`local_gain.local_gain_at`。mode_drive の `_local_gain_ratio` と同じ「効き始めからの量 × 車速」で引く）。meta の倍率は「表の傾きに対する倍率」なので、G/% にするには表の傾きも要る。そのため引数は meta だけでなく表そのもの。傾きが出ない・0 以下は既定 k。
  - 枠は 効き始め〜最大開度。枠に当たって誤差がさらに押す向きの間は積分を止める。0.3G 超えは誤差が負なので積分は戻す向きだけに働く。窓が埋まるまでは開度を保つ。
  - `StopDecelResult` の `presses`・`releases` は `cycles`（PI の周期数）に替えた。CSV の段名は `STEP` → `PI`。
- 呼び出し元: `mode_drive._finish_stopped` は走行に使った表を渡す。`pattern_drive`・`excite`（学習の走り終わり）は渡さない（学習中の pkl は無いか古い）。
- 単体テスト `test_research_stop_decel.py` を書き直した（13 件）: 局所の効き k（既定・表の傾き・倍率）・表なしで min へ接近して停車・表ありで 0.2G に近づく・meta の効き始めへ接近・途中の開度から始める（位置を読まない）・0.3G 超えで戻す・最大開度で頭打ち・窓が埋まるまで保つ・タイムアウト・CAN 断で DriveError・`load_brake_table`。スタブ車の G の数値は合否に使わない（範囲は広く取っている）。

**調整値**
