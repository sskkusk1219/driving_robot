# PID制御と調整方法

## 1. PID制御とは

目標値 r と実測値 y の差（偏差 e = r − y）から操作量 u を決めるフィードバック制御。

```
u(t) = Kp·e(t) + Ki·∫e(t)dt + Kd·de(t)/dt
```

例：車速追従なら r = 目標車速、y = 実車速、u = アクセル開度。

| 項 | 何に反応するか | 効果 | 強すぎると |
|---|---|---|---|
| **P（比例）** | 今のズレの大きさ | ズレに比例して押し返す。応答が速くなる | 振動・オーバーシュート |
| **I（積分）** | ズレの蓄積 | 定常偏差（P だけでは残るズレ）を消す | ゆっくりした大きなうねり、ワインドアップ |
| **D（微分）** | ズレの変化の速さ | ブレーキ役。行き過ぎを抑えて減衰を良くする | ノイズを増幅し、操作量がガタつく |

イメージ：P は「今どれだけズレているか」、I は「これまでどれだけズレ続けたか」、D は「この先どうズレそうか」を見ている。

ゲインは Kp, Ti（積分時間）, Td（微分時間）の形で書くこともある。

- Ki = Kp / Ti
- Kd = Kp · Td

## 2. Pythonでの実装（実用版）

教科書どおりの式をそのまま使うと実機では問題が出るため、よく使う対策を入れた離散実装。

```python
class PID:
    def __init__(self, kp, ki, kd, dt, u_min=0.0, u_max=100.0, d_filter_tau=0.05):
        self.kp, self.ki, self.kd, self.dt = kp, ki, kd, dt
        self.u_min, self.u_max = u_min, u_max
        self.alpha = dt / (d_filter_tau + dt)   # D項のローパスフィルタ係数
        self.integral = 0.0
        self.prev_y = None
        self.d_filt = 0.0

    def update(self, r, y, u_ff=0.0):
        e = r - y

        # D項: 偏差ではなく測定値の微分を使う（目標値ステップ時の跳ね上がり防止）
        if self.prev_y is None:
            self.prev_y = y
        d_raw = -(y - self.prev_y) / self.dt
        self.d_filt += self.alpha * (d_raw - self.d_filt)  # ノイズ対策
        self.prev_y = y

        p = self.kp * e
        d = self.kd * self.d_filt
        u_unsat = u_ff + p + self.ki * self.integral + d
        u = min(max(u_unsat, self.u_min), self.u_max)

        # アンチワインドアップ: 出力が飽和している方向には積分を進めない
        if u == u_unsat or (u_unsat > self.u_max and e < 0) or (u_unsat < self.u_min and e > 0):
            self.integral += e * self.dt

        return u
```

### 実装上のポイント

- **アンチワインドアップ**：アクセル100%に張り付いている間に積分が溜まり続けると、目標到達後も戻らず大きく行き過ぎる。飽和中は積分を止める。
- **測定値微分**：目標値が急変したときに D 項が暴れるのを防ぐ。
- **D項フィルタ**：車速信号のノイズを D 項が増幅しないようにする。

## 3. 調整（チューニング）のやり方

### 方法A：手動調整（実機で最も一般的）

1. **I=0, D=0 にして P だけ**にする。Kp を小さい値から少しずつ上げ、応答が速くなり軽くオーバーシュートし始める手前で止める。
2. **I を足して**定常偏差を消す。Ti を大きい値（I が弱い状態）から徐々に小さくし、ズレが消える速さとうねりのバランスで決める。
3. **必要なら D を足し**、オーバーシュートや振動を抑える。ノイズで操作量がガタつく場合は D を弱めるかフィルタを強める。
4. 目標値変化（ステップ・ランプ）と外乱の両方で動作を確認して微調整する。

ゲインは2倍・半分のように**倍率で振る**と、効く範囲を早く掴める。

### 方法B：ジーグラ・ニコルスの限界感度法

1. P のみで Kp を上げていき、**一定振幅で持続振動する**ゲイン Ku と、その周期 Tu を測る。
2. 下表から初期値を決める。

| 制御 | Kp | Ti | Td |
|---|---|---|---|
| P | 0.5 Ku | – | – |
| PI | 0.45 Ku | 0.83 Tu | – |
| PID | 0.6 Ku | 0.5 Tu | 0.125 Tu |

注意：応答がかなり振動的になりがち。**初期値として使い、そこから Kp を下げる**つもりで使うのが実用的。持続振動させてよい対象にしか使えない。

### 方法C：ステップ応答法（モデルを使う）

操作量をステップ状に変えたときの応答から、むだ時間 L、時定数 T、ゲイン K を読み取る（一次遅れ＋むだ時間モデル）。そこから ZN ステップ応答法、CHR法、IMC法などの式で初期値を計算する。

Pythonでログからモデルをフィッティング → シミュレーションでPIDを詰める → 実機に載せる、という進め方が効率的。

## 4. 速度追従でのコツ

車速トレース追従のような用途では、**PIDだけで追わせるより、フィードフォワード（FF）を併用する**方が追従が大きく良くなる。

- **FF**：目標車速と加速度から「このくらいのアクセル開度が必要」という値をマップや簡易モデルで先に出す（コードの `u_ff`）
- **PID**：FF で合わない残りのズレだけを補正する

FB だけだと「ズレてから直す」ため、加速の立ち上がりで必ず遅れる。FF が大部分を受け持つことで PID のゲインを控えめにでき、振動も抑えやすい。

アクセルとブレーキの切り替え付近は制御が不連続になりやすいので、不感帯やヒステリシスを設けると安定しやすい。

### 評価指標の例

- 目標との誤差のRMS
- 最大誤差
- 許容帯からの逸脱回数・逸脱時間

数値で見ると調整前後の比較がしやすい。
