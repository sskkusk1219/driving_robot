## 原因① 車速LPF（前回の修正）がランプ区間に定常偏差を作った

前回 Phase 3-3 で、フィードバック（トリム／速い補正層 PID）入力の**実車速だけ**に
時定数 0.25s の 1 次ローパスを入れた。これがランプ追従中に「勾配 × 時定数」の定常偏差を
恒久的に作っていた。

| 区間 | 制御が見ている偏差 | 実際の偏差 | 差（LPF由来） |
|---|---|---|---|
| +2.0 km/h/s 加速（78.6s） | **+0.07** | -0.43 | +0.49 |
| -2.0 km/h/s 減速（44.9s） | -0.26 | +0.23 | -0.50 |
| -5.0 km/h/s 減速（15.3s） | **-0.06** | +1.06 | -1.12 |

制御は「偏差ほぼゼロ＝完璧に追従している」と認識しているのに、実際には毎回きっちり
`勾配 × 0.25s` だけずれている。検証パターンは時間の約 90% がランプなので、**これだけで
p95≤0.4km/h は原理的に達成できない**。

**修正**: 基準速度にも同一のローパスを掛ける（＝偏差にフィルタを掛けるのと等価）。
ランプ追従中は偏差が一定なのでバイアスが出ず、ノイズ除去効果だけが残る。
`drive_loop._filtered_feedback()`。

## 原因② ILC が trim をプランに吸収する構造なので①が恒久化する

プラン更新則は `次回プラン = clip(Q(u_applied + L·e(t+Δ)) − FF基準, ±Δlimit) + FF基準` で、
`u_applied` は前走行で実際に適用した effort（＝プラン＋trim）。実測でも:

- `corr(Δplan, 前走行の trim) = +0.90`、Δplan_rms 1.90% ≒ trim_rms 1.86%

つまり ILC の実体は「trim をプランへ移す」機構。trim は①のバイアス付き偏差で動くので、
収束先は「フィルタ後偏差 = 0」＝**実偏差がバイアス値のまま**になる。Δplan_rms が反復ごとに
1.90% → 0.64% と縮んでいるのは、この誤った床へ収束しつつある証拠。①を直さない限り
ILC を何周回してもこの床は破れない。

## 原因③ 減速中に部分アクセルが要る領域のデータがモデルに無い

`|偏差|>1.0km/h` の 39.9秒（走行の 25.6%）の内訳は **減速 26.2s（65%）** / 加速 12.4s / 平坦 1.3s。
最悪は t=84-96s（68→44km/h）:

```
 t     ref |  run1 err  plan | run2 err  plan | run3 err  plan
 88.0  59.8 |  -3.21  +3.53 |  -1.74  +5.21 |  -3.60  +4.87
 90.0  55.8 |  -3.68  +3.64 |  -2.11  +6.28 |  -1.87  +6.37
```

要求減速度 -2.0km/h/s に対し、この車の惰行減速は 55km/h で -3.56km/h/s。**アクセルを踏んで
減速を緩める**必要がある領域で、ILC は 3 反復でプランを +3.6% → +6.8% まで持ち上げたが、
誤差は縮まず場所が移動しただけだった。

学習運転のペダル開度カバレッジを調べると、この領域のデータが存在しない:

| 速度域 | 開度 0.5-10% のサンプル | 開度 10-20% での Δa |
|---|---|---|
| 5-25 km/h | 6.0s | — |
| 25-45 km/h | 2.5s | +7.36 km/h/s |
| 45-65 km/h | 6.2s | +4.67 km/h/s |
| 65-85 km/h | **0.7s** | +4.71 km/h/s |
| 85-105 km/h | 3.3s | — |
| 105-125 km/h | 4.8s | — |

WLTP の緩減速で必要な Δa は +0.3〜+2.5km/h/s ＝ 開度 1〜5% 相当で、まさにこの空白域。
逆FFモデル（accel R²=0.93）はここを**外挿**するしかない。

**そしてこれはテストパターンの都合ではない。** 登録済み全 12 モードの要求減速度を
惰行カーブと突き合わせた結果:

| モード | 減速時間 | うち惰行より緩い | 割合 |
|---|---|---|---|
| 06_WLTP_ExHi | 128.2s | 116.0s | **90%** |
| 08_HWFET | 193.3s | 171.2s | 89% |
| 05_WLTP_Hi | 159.8s | 121.2s | 76% |
| 01_WLTP_Low,Mid,Hi,ExHi | 644.0s | 482.2s | **75%** |
| 07_UDDS | 421.8s | 260.0s | 62% |
| 11_NEDC | 179.8s | 57.7s | 32% |
| 12_AMA | 557.9s | 56.9s | 10% |
| （参考）検証パターン | 60.7s | 35.2s | 58% |

**本番の WLTP は減速時間の 75% がこの領域**で、検証パターン（58%）より要求が厳しい。

**修正（ユーザー選択: 惰行カーブから解析的にプラン生成）**:
必要 effort を「モデルの外挿」ではなく `Δa / ペダルゲイン(v) + 不感帯` で出す
（`Δa = a_req − a_coast(v)`）。この式は **Δa=0 → effort=0** が構造的に保証されるので、
データの無い低開度域が「外挿」ではなく「原点との内挿」になる。

学習運転から同定したペダルゲイン（実測値。IQR が狭く安定している）:

| 速度 | アクセル [km/h/s per %] | ブレーキ [km/h/s per %] |
|---|---|---|
| 25 km/h | 0.533 | 0.245 |
| 55 km/h | 0.293 | 0.538 |
| 85 km/h | 0.285 | 0.984 |
| 115 km/h | 0.343 | 0.984 |

モデルが検証済みの高開度域は温存し、外挿しかできない低開度域だけ置き換える
（|解析effort| ≤5% は解析 100%、≥15% はモデル 100%、間は線形）。

**オフライン検証**（実パターン `__verify_pattern__` 155.5s、実プロファイル・実モデル）:

緩減速区間の平均 +2.18% → **+3.63%**。ILC が 3 反復かけて到達した +6.4〜6.8% に、

## 原因④ 符号反転 KPI が現定義では p95 と両立しない

最大反転（9回/5s）が発生していたのは **t=62s ＝ 120km/h 巡航 ＝ 最も追従が良い区間**だった。

- CAN 車速は生値で、10Hz 隣接差の std は **0.22-0.25 km/h**（0-5km/h: 0.170 / 20-60km/h: 0.246 / 100-121km/h: 0.223）
- 旧しきい値は 0.05km/h ＝ ノイズの 1/5

`|偏差| < ノイズ` である限りゼロクロスは避けられないので、**追従が良くなるほど反転回数は
増える**。p95≤0.4（偏差をノイズに埋める）と 反転≤1回/5s（偏差を 0 から離す）は、
旧定義では論理的に両立しない。

| しきい値 | 最大反転/5s |
|---|---|
| 0.05（旧） | 9 |
| 0.10 | 9 |
| 0.20 | 6 |
| **0.30（新）** | **4** |

**修正**: `±0.3km/h を両側で超えた往復のみ 1 回と数える`（実測ノイズ std の約1.3σ）。
`product-requirements.md` の KPI 定義も更新した。

**正直に書くと**、これは「ノイズを数えない」ようにする変更で、これだけで ≤1回/5s を
満たすわけではない（同じログで 4 回/5s 残る）。残りは原因①③の追従精度改善で減らす。

## 原因⑤ best 選択・打ち切り判定が reward ノイズに埋もれている

p95 は 2.92 → 2.22 → **2.09** と単調改善しているのに、reward は run3 で -6.8 悪化した
（max 偏差が 3.82→4.38 と悪化したため）。degrade しきい値は `epsilon×3 = 3.0` なので、

1. 4 本目を「発散」と誤判定して打ち切り（`degraded: true`）
2. p95 の悪い run2（2.22）を最終結果として採用

**修正**: best・打ち切りを **(KPI合否, -p95, reward) の辞書順**にした。収束判定は
「p95 が 0.05km/h 以上改善、または p95 横ばいで reward が改善」を「前進」とみなし、
前進なしが 2 回連続したときだけ打ち切る。degrade は「best から p95 が 0.5km/h 以上悪化」。

## 原因⑥ ILC のクランプ張り付きとリード時間の過補正

- 補正クランプ ±4%（前回 10→4 に絞った）に **4.1 秒張り付き**。張り付き位置は
  緩減速の入口 t=81-82s と軌跡頂点 t=146.6s ＝**最も補正が必要な場所**だった → 8.0 に戻した
- リード時間 Δ = θ + τ = 2.665s は行き過ぎ。run2→run3 で誤差が縮まず位置だけ移動する
  位相振動が出ている → Δ = θ + 0.5τ = 1.683s に緩めた

なお `scripts/replay_plan_update.py` の相互相関はこの Δ の妥当性を判定できない。観測される
Δplan は前走行の trim 吸収が支配的（corr 0.90）で、測っているのは ILC のリードではなく
**trim の応答位相**だから（実際 Δ を 0.7→2.665s に変えても best_lag は 0.7-1.0 → 0.5-0.9 と
ほぼ動いていない）。今回の変更は「run2→run3 の位相振動」という症状と FOPDT の物理から
決めたもので、ツールによる裏付けは取れていない。

## その他の観測（今回は未対処）

- **停止保持**: ref=0 到達時に実車速 1.16km/h が残り、ブレーキ 17% でも 0.62km/h まで 4 秒
  かかる（max KPI 違反に寄与）。最終停止の詰めも減速モデルの問題。

## 次回検討事項

- **停止保持の詰め**: ref=0 到達時に 1.16km/h 残る問題（最終減速の定式化）
- **trim の権限設計**: 実効 kp が SIMC 上限で 0.657 に絞られ、寄与率 7%。プラン精度に
  全依存する構造でよいか
- **ペダルゲインの非線形性**: 現在は速度ごとに単一ゲイン（原点通過の線形）。実測では
  低開度ほどゲインが小さい傾向があり（55km/h の解析値 5.8% に対し ILC 収束値 6.4-6.8%）、
  開度依存の 2 点折れ線にする余地がある
