# 要求内容

## 概要

自動走行の制御を「人間のペダル操作スタイル」に再構成する。走行開始時に基準軌跡全体から
ペダル操作計画（ペダルプラン）をオフライン生成し、実行時はプランに沿ってペダルを保持しつつ、
小さく滑らかなトリム補正のみを行う。**学習サイクルの最終フェーズに検証走行（登録全モードを
カバーする約5分の専用パターン）を追加してサイクル内でKPI合格を確認し、学習サイクル完了後の
最初の自動運転から KPI（p95≤0.2 / max≤1.0 / 符号反転≤1回/5s）を満足させる。**

## 背景

### 経緯

C-6実機ゲート初回（2026-07-10）で、自動走行がアクセル⇔ブレーキを約1秒周期で交互踏みする
ギザギザ運転になり KPI も大幅悪化（p95=1.330 / max=5.205）した。直接原因は実効PIDゲイン過大
（kp=3.91×ゲインスケジュールscale上限3.0張り付き=11.7 %/(km/h)、SIMC適正≈1.6の約7倍）で、
応急対策 B-8 を旧ステアリング（20260707-kpi-speed-tracking-fix）に計画した。

その計画レビューでユーザーから本質的な要求が提示された:
**「現在の制御でKPIを満足して、人間のような運転ができますか？できない場合はコードの
大幅修正をしても良い」** → 現行（B-8込み）は20HzでFF+PID+ILCを毎サイクル合成しペダルを
連続変調する構造であり「開度なるべく一定・調整は時々」にはならない、と判断。
本ステアリングで制御アーキテクチャを再構成する（2026-07-11 ユーザー承認）。

### 人間のペダル操作スタイル（ユーザー要求原文）

> 発進や加速はなるべくクリープで、クリープで足りない加速はアクセル開度を踏んで加速していく、
> 加速/一定速/減速におけるペダル開度はなるべく一定で、減速はなるべくエンジンブレーキで、
> エンジンブレーキで足りない減速はブレーキ開度を踏んで減速する。停止は停止中にブレーキ開度を保つ

「なるべく開度一定」の解釈: 開度を固定するのではなく、**変化はゆっくり・滑らかに・必要なときだけ**
（人間はWLTPを±0.5km/h程度で追従できる＝小さな調整は常時行うが、踏んだり離したりはしない）。

### KPI達成の枠組み（2026-07-11 ユーザー指示で改訂）

- **学習運転が終了したら、次に行う自動運転で KPI を満足している必要がある**（本番走行を
  収束の場にしない）
- そのため学習サイクルの最終フェーズに**検証走行**を追加する: 登録済み全走行モードの速度域・
  加減速率・巡航・停止を約5分にカバーする**検証専用パターン（ユーザー選択なし・自動生成）**を
  ILC無効で走行し、KPI合格でサイクル完了（不合格ならモデル再学習して再走行、上限5本・
  合格で早期終了）。対象モードそのもののリハーサルはしない（12_AMA=87分級のモードで
  サイクルが破綻するため）
- ILC はモード別の**任意の強化**に位置づけを変更（本番自動走行の正常完了で従来どおり学習・
  適用するが、KPI達成の前提にしない）
- 偏差0.5km/h超で速い補正層が介入する安全網により max≤1.0 は常時担保

### モード解析の事実（2026-07-11 全12登録モードの基準軌跡から机上計算）

車両定数（engine_brake=1.6km/h/s・creep 4.94km/h/0.065km/h/s、余裕±0.15km/h/s・1s平滑）で
分類すると、各モードが**軌跡上要求する**ペダル切替（アクセル⇔ブレーキ、惰行挟み2s以内）は
1.0〜3.7回/min（06_WLTP_ExHi 1.3、09_US06 3.7 など）。問題の本質は総切替数ではなく
**軌跡が要求しない不要な切替**（2026-07-10 実測: 要求1.3に対し39.4回/min）。したがって
評価指標は「不要切替 = 実測切替 − 軌跡要求切替」とし、**基準軌跡から自動計算する
（モードごとの設定は不要）**。人間的な操作ができれば不要切替は≈0になる。

## 実装対象の機能

### 1. ペダルプラン（PedalPlanner / PedalPlan — 新ドメイン）
- 走行開始時に基準軌跡全体からフェーズ列（DRIVE / COAST / BRAKE / STOP_HOLD。クリープ発進・
  クリープ保持は COAST に含む）と名目effort系列を生成
- クリープで足りる区間はペダルなし、減速はまずエンジンブレーキ（COAST）、
  必要減速がエンジンブレーキ超のときのみ BRAKE、停止中は STOP_HOLD（停車保持ブレーキ開度）
- 最小フェーズ長で micro-phase をマージし、不要切替をプラン段階で構造的に排除
- 名目effortはFFモデルのオフライン評価＋ゼロ位相ローパスで滑らかに整形

### 2. トリム制御（TrimController — DriveLoopのPID置換）
- |偏差| ≤ 0.1km/h: 出力凍結（ペダルを動かさない）
- 0.1 < |偏差| < 0.5: 低速PI（出力変化レート制限＋量子化）＝人間の「少し踏み足す/緩める」。
  レート等の定数は**検証走行でp95≤0.2を出せる水準**に校正する（ILCに頼らないため、
  過度に遅くしない）
- |偏差| ≥ 0.5: 速い補正層（SIMC由来PIDゲイン×ゲインスケジュール、scale上限1.5=B-8-3引継）
- ペダル権限はプランのフェーズが支配: DRIVE中はアクセルのみ・BRAKE中はブレーキのみ・
  COAST/STOP_HOLD中は速い補正層以外踏まない

### 3. 学習サイクルの検証走行フェーズ（VERIFY — 新規）
- 検証専用パターンの自動生成: DB登録済み全モードの最高速度・巡航速度帯・加減速率分布・
  停止回数を包絡する約300秒の軌跡（`build_verification_trajectory`）。ユーザー選択なし
- REFINE_2 完了後に VERIFY フェーズ: 検証パターンを**ILC無効・プラン+トリム構成**で走行 →
  KPI判定（p95≤0.2 / max≤1.0 / 反転≤1回/5s）→ 合格で早期終了、不合格なら走行データを加えて
  モデル再学習＋プラン再構築して再走行（**上限5本**）。上限到達で未達なら WARNING 付き完了
- WebUI の学習サイクル進捗に VERIFY フェーズと各走行のKPI値を表示

### 4. 不要切替の計測（B-8-4 の移管・再定義）
- KPIMonitor にアクセル⇔ブレーキ交互踏みカウントを追加し、tuning_cost にペナルティ項を追加
- analyze_session.py は「軌跡要求切替（ログ内の基準軌跡から自動計算・設定不要）」との差分
  ＝**不要切替/min** を表示（合否ゲートではなく観測指標。人間的操作なら≈0になる）

## 受け入れ条件

### ペダルプラン
- [ ] 全12登録モードでプラン生成が成功し、プランのペダル切替回数が軌跡要求と一致（±1回/走行）
- [ ] クリープ発進（発進直後のペダルなし区間）・エンジンブレーキ優先・停止中ブレーキ保持が
      プランに反映されている（WLTP_ExHi ほかでフェーズ列を目視確認）

### トリム制御
- [ ] 単体テスト: 3層（凍結/低速/速い）の遷移・レート制限・量子化・バンプレス切替・
      フェーズ権限・アンチワインドアップ
- [ ] pytest tests/unit＋integration 全緑、ruff/mypy 新規エラーなし

### 検証走行フェーズ
- [ ] 検証パターンが登録全モードの速度域・加減速率を包絡している（机上検証スクリプトで確認）
- [ ] 学習サイクルが VERIFY フェーズを実行し、KPI合格で完了・不合格で再学習ループ・
      上限5本で打ち切り（単体テストで遷移を検証）

### 実機検証（ユーザー実施）
- [ ] 学習サイクル（VERIFY含む）が KPI 合格で完了する
- [ ] **サイクル完了後の最初の自動運転（登録モード）で p95≤0.2 / max≤1.0 / 反転≤1回/5s を満足**
- [ ] ペダル挙動の目視: 開度なるべく一定・クリープ発進・エンジンブレーキ優先・停止中保持。
      不要切替 ≈0（analyze_session の観測指標）

## 成功指標

- 学習サイクル完了 → 最初の自動運転からプライマリーKPI 3項目達成
- ペダル操作が人間的（不要切替≈0、accel ON 110-135km/h帯 ≤10回/min、
  |偏差|<0.3km/hでのペダル切替ゼロ）

## スコープ外

- WebUIのフェーズ表示・プラン可視化（動作はログ/analyze_sessionで確認。VERIFY進捗表示は対象内）
- FFモデルのアルゴリズム変更
- KPIしきい値の変更
- 学習運転（LearningLoop・データ採取パターン）の変更
- 旧ステアリング B-8-1（PID不感帯）/B-8-2（ブレーキ抑制ガード）の単体実装
  （本アーキテクチャのトリム凍結帯・フェーズ権限に吸収）
- ILC を KPI 達成の前提にすること（モード別の任意強化として存続）
