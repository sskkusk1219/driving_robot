## 3. 各案

### 3.1 P と DOB をさらに強くする

- 未達の差が大きいのは ② p95（0.48〜0.68 に対し 0.4）。p95 を決めているのは 0.02〜0.2 Hz の遅い成分（`183428` の分析: 0.1 Hz より遅い成分を消せれば p95 0.29 の計算）で、FB の強さでしか下げられない
- 2t の周波数応答では、余裕（位相 45°・ゲイン 6 dB）を満たす最小は c 6（ブレーキ 5）・Tq 係数 5。c 12.5・Tq 20 で止めていた理由は往復の KPI だけ
- 試す順: c 8 → c 6、Tq 係数 10。新しい決まり B で 1 本ずつ判定する。念のため、ばたつきの帯（0.9〜1.7 Hz）が 0.015 km/h を超えないかも見る

### 3.2 「D 項を足す」について（足さない）

- D 項（偏差の微分 ＝ 加速度の差に比例して補正する）の役目は、今の DOB がすでに担っている。DOB は「実加速度 − 予測加速度」を Tq でならして返すので、Tq を短くするほど D 項に近づく
- D 項を別に足すと、1 周期差の加速度のノイズ（約 0.47 km/h/s）がそのまま開度に乗る（Kd 0.3 で約 0.4% の揺れ）。また純粋な遅れ L を通るので Kd は 1 未満に抑える必要があり、伸ばせる幅は小さい
- → 同じ効果は Tq 係数を下げる方が、ならしが効いている分だけ安全に得られる。D 項は足さず、Tq で調整する（3.1）

### 3.3 K 基準の折れ目（37%）: FF の窓を短くする

- FF は「遅れ L 先を中心にした 1 秒の窓」（`need_window_s` 1.0）で基準の傾きを見る。1 秒刻みの基準の折れ目を 0.4〜0.6 秒前から追い、ペダルを早く戻す・踏み替える（US06 487 s・AMA 302 s）
- `need_window_s` を 1.0 → 0.5 → 0.3 秒と短くする。窓を広げていたのは往復を減らすためで、今はその縛りがない
- 合わせて、踏み込みと戻しで先読みの時間を分ける: 踏み込みは遅れ L、戻しは 2o-9 で測った戻る時間（遅れ ＋ 深さ ÷ 速さ）。深いブレーキ（19% など）の抜き始めの時刻を正しく決めるため

### 3.4 低速（L 発進 24%・S 停車へ 15%）: DOB を切らずに使い分ける

今は 7.5 km/h を境に DOB を 0 にしているので、(1) その日のずれ (2) 低速の表の外れ (3) 境目での段差（WLTP 983 s: 0.46% → 0）が同時に出ている。

- **(a) 切らずに薄める:** 7.5 km/h → 停車速度にかけて、DOB の上乗せを 1 → 0 へ連続に下げる。境目の段差をなくす
- **(b) 発進と停車ごとに持ち越す:** 発進用・停車用に低速専用の推定を 1 つずつ持つ。更新はその場面の間だけ（発進: 動き出してから 7.5 km/h まで／停車: 7.5 km/h から停車保持の手前まで）。次の発進・停車まで値を持ち越す
  - 2q ① の「停車保持中に積み上がる」は、この形では起きない（停車保持は更新しない）
  - 段3b で全モード同じ向きに出た偏り（発進側 −0.2〜−0.4・停止側 +0.3〜+0.9 km/h/s）は、1〜2 回の発進・停車で推定が吸う見込み
  - 走った状態から学ぶので、モード学習には当たらない
- **(c) 停C の τ:** min(普段の τ, 残り時間) にして、普段より弱くならないようにする（段4 の論点 2 (c) と同じ）

### 3.5 微速（C 惰行の補助 10%・W 微速の減速）: 根本はブレーキでのクリープ車速の調整

#### なぜ微速で惰行の補助が出てくるか（UDDS 1256 s）

1. 基準が 1.6 km/h で 4 秒一定。FF のブレーキ 8.4〜8.9% が強く、車は 0.44 km/h まで落ちた（偏差 約 −1.2）
2. 続く行で FF の計画が惰行（両ペダル min）になった（1.6 km/h を保つ要る加速度はほぼ 0）
3. 惰行の補助は「計画が惰行の行」かつ「基準も実車速も停車速度より上」で入る。偏差が入る条件 0.5 km/h を超えていたので入った
4. 遅れているのでアクセル側を選び、発進側の表を逆に引いて 10.2%（ほぼ動き出す開度）。最低保持 1.8 秒の間は離さず、3.96 km/h まで行き過ぎた

WLTP 444.6 s（+1.62）も同じ形（0.3 km/h まで落ちた後、ブレーキ 8.4% でクリープに負けて速くなり、FF が 0.4 秒惰行・補助のブレーキ 6.8% も弱い）。

→ **惰行の補助は結果として出てきただけ。根本は、ブレーキだけでクリープとつり合わせて微速を保つことができず、惰行の行に落ちること。**

#### 決まり: アクセルを使うのは「要る加速度 ＞ クリープ加速度」のときだけ

- 条件: **要る加速度（遅れ L 先の基準） ＞ a_creep(v) ＋ 余裕** のときだけアクセルを使う。それ以下はブレーキで調整する。両者がほぼ等しい帯は惰行（両ペダル min）にし、境目でペダルが入れ替わらないようヒステリシスを付ける
- a_creep(v): 両ペダル min（惰行）のとき、その車速で出る加速度。停車からの動き出し付近で最大（手順2 の推定で約 1.3 km/h/s）、車速とともに下がり、クリープ車速で 0、それより上はマイナス（惰行の減速）
- 車速の条件（「クリープ車速以下ではアクセルを使わない」）だけでは足りない（ユーザー指摘 2026-10-21）。加速度の条件で全部の場面が分かれる

| 場面 | 車速の条件だけ | 加速度の条件 |
|---|---|---|
| 1.6 km/h で一定（UDDS 1256 s） | ブレーキ ✓ | 要る 0 ＜ クリープ → ブレーキ ✓ |
| 停車から強い発進（クリープ車速以下で加速度が大きい） | ブレーキ ✗（加速が足りない） | 要る ＞ クリープ → アクセル ✓ |
| クリープ車速の少し上で、ゆるい加速 | アクセル（ほぼ正しい） | 要る ＞ クリープ（ほぼ 0）→ アクセル ✓ |
| クリープ車速の少し上で一定 | アクセル ✗（惰行で減速するので、本当は少し要る） | 要る 0 ＞ クリープ（わずかにマイナス）→ アクセルを浅く ✓ |

- 入れる場所:
  - FF の計画: ペダルの選び方をこの条件にそろえる。強い発進では、今ある先置きがそのまま働く
  - 惰行の補助・P・DOB: 補正後の要る加速度（要る加速度 ＋ 偏差 ÷ τ − 推定）にも同じ条件をかける。UDDS 1256 s では、遅れ 1.2 km/h を 3 秒で戻す分（約 0.4 km/h/s）を足してもクリープで出せる範囲なので、アクセル 10.2% は出ない

#### 微速は「ブレーキとクリープのつり合い」として扱う

- 今の FF は微速でも停止側の表（車速 × 開度 → 加速度）を逆に引く。この表は止まっている・一定の場面の行から作られ、走りながらでは外れる（段3b・段4。場面によって外れる向きが逆）
- 微速の保持に要るのは **つり合い開度 u_bal(v)**: その車速でクリープとブレーキがつり合い、加速度 0 になるブレーキ開度
- 制御: u ＝ u_bal(基準車速) ＋ 偏差に応じた小さな補正（P＋I）。つり合いの近くではブレーキの効きが約 0.9 km/h/s/% と強いので、補正のゲインは小さく取る
- u_bal(v) の材料: 手順2 のコーストダウンの最後に 0.53%/s で少しずつ踏み込んで止める区間（段2l-6b）が「ブレーキ開度 × 微速での減速」の行になっている。足りなければ、クリープ車速から少しずつブレーキを踏んで止まるまでのゆっくりした掃引を手順2 に 1 つ足す（1 分程度）

#### 惰行の補助の対症療法（上の決まりと合わせて）

- 微速（クリープ車速 ＋ α 以下）では、動き出す開度を下限にしない
- 最低保持時間の途中でも、偏差の符号が変わったら離す

#### 確かめておきたい点

- 前に見たモデル `fwd_model_20261017_022008.pkl` では、表の開度 0 の列の低速の値が 1.25 km/h で +0.07、3.75 km/h で −0.10 km/h/s で、手順2 の推定値（クリープ加速度 1.26〜1.33 km/h/s）と大きく違った
- 今のモデル `003112` でも同じなら、FF は「ブレーキを離してもほとんど加速しない」と思い込んでいる。WLTP 444.6 s（ブレーキを抜いて惰行にしたらクリープに押されて速くなった）と辻褄が合う
- → a_creep(v) は表の開度 0 の列ではなく、手順2 の 2-0（クリープの測定）や停車から動き出す行から別に持つ方が確実

#### pkl `fwd_model_20261019_003112.pkl` の確認結果（Claude 確認 2026-10-21）

開度は min からの量（＋ アクセル／− ブレーキ）。値は km/h/s。

**開度 0（両ペダル min）での加速度**

| 車速の行 | 本体の表（`accel`） | 発進側の表（`launch_accel`） | 停止側の表（`stop_accel`） |
|---|---|---|---|
| 1.25 km/h | −0.21 | **+1.56** | **+1.53** |
| 3.75 km/h | −0.33 | +0.07 | +0.01 |
| 6.25 km/h | −0.44 | −0.44（本体と同じ） | **0.00** |

- 発進側・停止側の表から読むと、クリープ加速度は 1.25 km/h で約 1.5、3.75 km/h でほぼ 0。クリープ車速は約 4 km/h。手順2 の推定値（1.26〜1.33）とも合う
- 本体の表は今のモデルでも、低速で「惰行なら減速する」と言っている。低速の行は発進側・停止側の表で置き換える設計なので本体の値は使われないが、**a_creep(v) を本体の表から取ってはいけない**

**見つかった点（制御への影響が大きい順）**

1. **0〜5 km/h の車速の刻みが粗い。** 行は 1.25・3.75・6.25 km/h（2.5 km/h 刻み、`launch_speed_rows` [1.25, 3.75]・`stop_speed_rows` [1.25, 3.75, 6.25]）。クリープ加速度はこの 1 マスの間で 1.5 → 0 と変わる。UDDS 1256 s の「1.6 km/h で保持」はちょうどこの間で、線形補間の誤差がいちばん大きい所
2. **停止側の表に「ちょうど 0」の平らな帯がある。**
   - 1.25 km/h: −3.25% で 0.00
   - 3.75 km/h: −1.25〜0% で 0.00〜0.01
   - 6.25 km/h: −2.25〜0% の 2% の幅がすべて 0.00
   - 6.25 km/h で走っている車が、ブレーキを 2% 変えても加速度がまったく変わらないのは物理的に不自然。止まり切った行（車速 0 で減速が出ない）が混ざったか、埋め方の結果と読む（推測）
   - 要る加速度が 0 付近で逆引きすると、平らな帯のどこでも答えになる。そのため「惰行（0%）」を返したり、少しマイナスを要るとすぐ急な所（1.25 km/h では −3.25 → −4.25% の 1% で 0 → −2.0）へ跳んだりする。報告書の「FF が惰行になる」「ブレーキが急に深くなる」と同じ形
3. **6.25 km/h の行で、発進側と停止側の表が食い違う。** 同じ車速・開度 0 で、発進側 −0.44（本体）・停止側 0.00。7.5 km/h 未満をどちらの表で引くかで FF の答えが変わる
4. **UDDS 1256 s のブレーキ 8.4〜8.9% について（推測・未確認）。** 停止側の表では、1.6 km/h でつり合うブレーキは約 −3%（絶対値で約 7.2%）。実際の FF の 8.4〜8.9% は、pkl の動き出す開度 `launch_breakaway_u_pct`（−4.33%、絶対値 8.53%）とほぼ同じ。微速の保持で「止まっている車のための開度」が使われた可能性がある。段3a の C14 で分かった「走っている車には強すぎる」と同じこと。UDDS `095014` の 1250〜1260 s の行で、FF がどの表・どの開度を使ったかを確かめる

**3.5 の決まりへの反映**

- 「要る加速度 ＞ a_creep(v) ＋ 余裕 のときだけアクセル」はそのまま使える。ただし a_creep(v) は**発進側・停止側の表、または専用の測定**から取る
- 0〜5 km/h では、a_creep(v) と u_bal(v) を 0.5 km/h 程度の細かい刻みで持つ
  - a_creep(v): 手順2 の 2-0 で、ブレーキを min に離して停車からクリープ車速まで自然に加速する区間を記録する
  - u_bal(v): クリープ車速から少しずつブレーキを踏んで止まるまでの区間から取る
- 停止側の表の「ちょうど 0」の帯は、止まり切った行を学習から外して作り直すのが先

### 3.6 アクセルのヒステリシス補償（新しく足す候補）

- 段4 で、全 5 モードと手順2 のどれでも「戻している最中は表より加速が弱く（−0.1〜−0.27 km/h/s）、踏み増している最中は強い（+0.03〜+0.21）」。動かす向きで効きが変わる、典型的なヒステリシス
- 4-3 C はこれを表で「予測」しただけで、FF の計画に反映していなかったため効かなかった（DOB の補正が消えただけ。加速中 +0.38% の踏み足しが 0 になった）
- 補償: 指令を出す直前に **u_out ＝ u ＋ h × (動かしている向き)**。h は手順2 の踏み増しと戻しの行の差を感度で割って求める（今のデータで 0.3〜0.4% の見込み）。向きの判定にはヒステリシスを付け、細かい揺れで符号が入れ替わらないようにする
- FB による動きも含めて実時間で効くので、今 DOB が「外乱」として拾っている分（加速中 +0.38%）を構造として直せる
- 注意:
  - 試験車はペダルを読むシミュレータなので、実車で同じ特性とは限らない。h は必ず手順2 で車ごとに測る
  - 手順2 での差（±0.07 程度）とモード走行での差（±0.2）が違う。向きを変える速さにも依存している可能性がある
  - → **まず机上で**、過去の CSV の r を「向き × 変える速さ」で分け、h が一定とみなせるかを確かめる
