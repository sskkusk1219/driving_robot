### ① 一時停止で非常停止（原因を確認済み）

| 項目 | 内容 |
|---|---|
| 起きたこと | 07:58:22.382 に一時停止を要求 → 07:58:22.833 に「制御を作るのに **0.41 秒**」→ 同じ時刻に「CAN 車速が 0.4s 更新されていません（バス無音の疑い）」で自動の非常停止（85ead083 のメッセージ） |
| 一時停止の仕組み | 押された時点の車速を保つ「定速 6 秒の走行モード」をその場で作り、それで制御する（`src/robot/core/mode_drive.py` `_pause_begin`）。作る処理は制御の周期の中で行う（11-16 実機で、別スレッドで作ると 2.7 秒かかりモードが先へ進んだため、周期の中で作る形に直した経緯がある） |
| CAN 車速の「古さ」の判定 | 車速は同じイベントループの中で受信してためている（`src/robot/core/can_reader.py`）。読むときに最後の受信から **0.4 秒**を超えていれば「バス無音」として止める |
| なぜ非常停止になったか | 制御を作る 0.41 秒の間、イベントループが止まって CAN を受信できなかった → 作り終えた直後の読みで「0.41 秒古い」→ 0.4 秒を超えたので非常停止。**CAN は実際には無音ではなかった（自分で止めていた）** |
| 作る時間のばらつき | 07:58 は 0.41 秒、08:03（303e9d45）は 0.04 秒。11-16 の実装時の記録は 0.02〜0.35 秒。どちらもランナー起動後 1 回目の一時停止なので「初回だけ遅い」ではない。ばらつく理由は未確認 |
| 一時停止の制御そのもの | 08:03 の走行（303e9d45）では正しく動いた: モードの時刻 28.75 s で止め、38.34 km/h を 30 秒保ち、28.75 s から再開 |

## 各段の内容

### 段1: 一時停止用の制御を別スレッドで作る

**内容** — 一時停止を受け付けた周期でモードの時刻だけを止め、一時停止用の制御は `asyncio.to_thread` で作る。作っている間は本体の制御を止めた時刻のまま回す（CAN は毎周期読む）。その間の行は一時停止の扱い（KPI 外）。作り終えたら切り替える。作っている間の再開・走行終了では作った結果を捨てる。

**変更**
- `tests/research/mode_drive.py`（同じ差分を `src/robot/core/mode_drive.py` へ。両者の差は `resolve_database_url` まわりだけのまま）
  - `_pause_begin`: 時刻を止め、`asyncio.to_thread` で作り始める。作っている間は section に `_PAUSE`・`paused=1`
  - `_pause_cycle`: 作っている間は本体の `_cycle(止めた時刻)`、作り終えたら一時停止用の制御（`_pause_switch_if_built`）
  - `_pause_exit`: 作っている途中の再開は結果を捨てて再開。走行の終わりでも捨てる
  - 別スレッドの表示だけを捨てる `mute_this_thread_stdout`（`redirect_stdout` はプロセス全体の出力を捨て、本体の警告まで消すため）
- 同じ時刻で `_cycle` を繰り返しても問題なし（I は dt=0 で積まない・D の傾きは幅 0 で 0）

**結果**（Claude 確認 2026-11-23）
- `tests/research/test_research_pause.py` 13 件（新規 4）・`tests/unit/test_cancel_guard.py`・`test_emergency_stop.py` 通過、ruff OK
- スタブ（WebUI・WLTP Low）: 「モードの時刻 26.75s で止めます … 保つ制御を別スレッドで作ります」→「切り替えました … 制御を作るのに 0.03 秒（作っている間 1 周期）」。再開・走行終了まで異常なし。車速の保ち方はスタブでは判断しない（実機で見る）

### 段2: 一時停止中に線を流さない

**再現**（Claude 確認 2026-11-23、スタブ）— 一時停止中に 8 秒あけて 2 枚撮った: 横軸の目盛り（15・20・25 …）は動かない。実測・ペダルの線が左へ流れる（ペダルの山が左へ移動）。原因は「議論で確認した事実」② のとおり（点の位置を毎回 `ts − driveStart` で計算し直す）

**変更** — `auto-drive.js` の `DriveMonitorScreen`: 点を部品の中の `ptsRef` に取り込むときに経過秒を 1 回だけ決める（`sample.mode_time_s` があればそれ、無ければ受信時刻 − 起点）。`trace` はその値で描く（共有の `realtimeBuf` は読むだけ）
