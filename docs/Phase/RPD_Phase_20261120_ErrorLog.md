# エラーページ（エラーログの記録と表示）（RPD_Phase_20261120_ErrorLog）

作成日: 2026-11-20 / 対象: `driving_robot`

**状態: クローズ（2026-11-20）** — スタブ・実機（API で非常停止）で確認済み。ユーザーが画面のスクリーンショットを確認して了承

## 1. なぜ作るか

いま WebUI でエラーが見られるのは、セッションを作るジョブ（学習・自動運転・手動運転）の「メッセージ」タブだけ。
次のものは画面のバッファ・トースト・tmux・ファイル（`logs/runner_idle.log`）にしか出ず、サーバーを止めると見られなくなる。

- 初期化・キャリブレーションの失敗（`job_manager.py` 冒頭のとおり「セッションを作らない」）
- 待機中の見張り（CAN 断など）・非常停止
- 計画の準備の失敗、シーケンスの途中停止
- サーバーの例外、ブラウザ側のエラー（赤いトースト・画面のプログラムの不具合）

## 2. 決定事項（2026-11-20 の議論）

| 項目 | 決定 |
|---|---|
| 置き場所 | サイドバーの「ログ」の下に新ページ「エラー」 |
| 範囲 | どんなエラーでも（上の全部＋セッション中のもの＋ブラウザ側） |
| 警告 | 残す（黄。エラーは赤） |
| 非常停止 | 残す（きっかけ＋終了処理の結果を 1 件に） |
| 単位 | できごと 1 件ごと＋直前の進行メッセージ |
| 確認済み・削除 | 両方できる |
| サイドバーの件数 | 出さない |
| 保存期間 | ずっと残す（DB） |

## 3. 「できごと 1 件」のまとめ方（記録の規則）

| きっかけ（source） | いつ 1 件にするか | 水準 |
|---|---|---|
| ジョブ（job） | ジョブの終わり（`JobManager._settle`）に 1 件。異常終了ならエラー、正常終了でも途中に警告・エラーの行があれば「警告ありで完了（N 件）」。ジョブ中の警告・エラーの行は本文に並べる（行ごとに別の件にしない） | 終了コード 0 以外 → エラー／0 で警告あり → 警告 |
| 非常停止（emergency） | `_enter_emergency` で 1 件（きっかけ: 画面／スイッチ／AC 断／自動＋理由）。そのときのジョブが終わったら、ジョブの件を別に作らず、この件に終了処理の結果を書き足す | エラー |
| 待機中（idle） | ジョブの外のランナーの警告・エラーの行（`_say_idle`）。同じ文が 60 秒以内に続いたら回数を足す | 行の水準 |
| 計画の準備（prepare） | 準備が error になったとき 1 件 | エラー |
| シーケンス（sequence） | 段のジョブの失敗は、そのジョブの件に「シーケンス名・何段目」を付ける。ジョブ以外の理由で止まったとき（段を始められない等）だけ別に 1 件 | エラー |
| サーバー（server） | `src`・`uvicorn.error` ロガーの WARNING 以上のうち、上の経路で記録済みでないもの（API の例外のトレースバックを含む）。同じ文が 60 秒以内なら回数を足す | 行の水準 |
| 画面（browser） | 赤いトースト（`showToast(…,'error')`）、`window.onerror`、`unhandledrejection`。ブラウザから POST。同じ文が 60 秒以内なら回数を足す | エラー |

各件に付けるもの: 日時（最初・最後）、回数、水準、きっかけ、題名、本文（理由）、直前の進行メッセージ（最大 50 行）、関連（ジョブの種類・job_id・車・session_id・シーケンス名）、確認済みの日時。

**安全の約束**: 記録は制御を止めない・遅らせない。書き込みは非同期のキューで、失敗してもログに 1 回出すだけ（記録のハンドラ自身のログは拾わない＝無限ループ防止）。ブラウザ側も POST の失敗でトーストを出さない。

### 6.3 確認中に直したところ
- 非常停止の件に、ランナーの「終了処理:」の行（INFO）が入っていなかった → 非常停止の件が開いている間は書き足す（`JobManager._say_idle`）

### 6.4 実機（8080・本番 DB。操作はすべて API）
- 本番 DB に `scripts/setup_db.py` で `error_events` を作成（既存テーブルは変えていない）
- 実機 WebUI 起動 → 初期化（終了コード 0）: 0 件
- 待機中に `POST /api/v1/drive/emergency` → 1 件「非常停止（画面の非常停止ボタン）」。本文: 待機中・終了処理: 原点復帰 → サーボOFF → 切断（10.3 s）→ 完了（13.7 s）・常駐ランナー終了（終了コード 130）
- `reset-emergency` → 本文に「非常停止を解除しました」。初期化し直して READY
- uvicorn を SIGINT で停止（ランナーは原点復帰 → サーボOFF → 切断 → 完了）。停止でも件は増えない（本番 DB の件数 1）

### 6.5 計画と違えたところ（実装時の判断）
- 利用者の停止ボタンで止めた走行（終了コード 130/143・非常停止でない）はエラーの件にしない。途中に警告・エラーの行があれば警告の件「利用者が停止（…N 件）」
- 重複まとめで回数を足したときは確認済みを外す（新しい発生を未確認として見せる）
- 非常停止中はエラーページを開けない（非常停止の画面が先に出る。今の作りのまま）
