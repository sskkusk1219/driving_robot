# 要求内容

## 概要

Ridge 逆FFモデルが原理的に推論できない領域（停車保持・クリープ・惰行・不感帯）を、車両プロファイルに保存する物理定数で補う。定数は学習時に観測可能なものだけ自動推定して上書きし、プロファイル編集画面でユーザーが手動調整もできる。

## 背景

逆FFモデルは `fit_intercept=False` で学習しているため、原点 (v0=0, 全Δv=0) では必ず出力 0 になる。しかし AT 車は停車中もクリープで前進するため、止め続けるにはブレーキが必要で、これは Ridge では表現できない。同様に、クリープ・惰行（エンジンブレーキ）・ペダル不感帯（遊び）も滑らかな線形モデルでは表現が難しい。これらを車両固有の物理定数で補完することで、低速・停車・惰行域の挙動を改善し、微小開度のチャタリングを抑制する（PRD「符号反転5秒に1回以下」KPI に寄与）。

参考: `driving_simulator/src/speed_predictor.py` のクリープ/エンジンブレーキ定数。

## 実装対象の機能

### 1. フィードフォワード物理定数（FeedforwardParams）
車両プロファイルに以下6定数を保存する:
- `creep_speed_kmh`：クリープ車速
- `creep_rate_kmhs`：クリープ加速率
- `engine_brake_decel_kmhs`：エンジンブレーキ減速量
- `stop_brake_opening_pct`：停車時ブレーキ開度
- `brake_deadband_pct`：ブレーキ不感帯（遊び）★
- `accel_deadband_pct`：アクセル不感帯（遊び）★
（`stop_speed_kmh`＝停車判定しきい値は内部定数）

### 2. FFでの定数利用
`FeedforwardController.predict` が定数を使って停車・クリープ・惰行レジームをオーバーライドし、不感帯で微小開度を 0 にスナップする。

### 3. 学習時の自動推定・更新
学習実行時、ログから観測可能な定数だけ推定して上書きし、データ不足の定数は既存値を保持する。

### 4. プロファイル編集UI
編集画面で6定数を表示・変更でき、学習実行後は自動更新された値が反映される。

## 受け入れ条件

### FeedforwardParams 永続化
- [ ] `vehicle_profiles` に `feedforward_params`(JSONB) 列を追加（既存行は NULL → デフォルト）
- [ ] リポジトリが読み書きでき、NULL/欠損時はデフォルト値を返す

### FF 定数利用
- [ ] 基準が停車（v0・先読みが停車しきい値以下）のとき brake=`stop_brake_opening_pct`、accel=0
- [ ] 目標が `creep_speed_kmh` 以下かつ微小要求のとき pedal≈0
- [ ] 目標減速が `engine_brake_decel_kmhs` 以下のとき brake=0（惰行で足りる）
- [ ] `accel_deadband_pct`/`brake_deadband_pct` 未満の予測開度は 0 にスナップ

### 自動推定
- [ ] 観測サンプルが十分な定数のみ上書き、不足時は既存値保持
- [ ] 学習成功時にプロファイルへ保存され、レスポンスに含まれる

### UI
- [ ] 編集画面で6定数を表示・編集・保存できる

- `pytest tests/unit/` 全通過、ruff/mypy が本変更分でクリーン

## スコープ外
- 不感帯（accel/brake deadband）の自動推定（ログからの信頼推定が困難なため、ユーザー手動調整＋デフォルト保持とする）
- ジャーク制限・アクチュエータ応答遅れ（制御チューニング側の別概念）
