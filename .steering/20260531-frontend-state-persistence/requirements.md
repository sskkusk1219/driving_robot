# 要求仕様: フロントエンド状態のページリロード後保持

## 概要

F5キー（ページリロード）を押すと、右上に表示されていた「選択中のプロファイル」と「走行モード」が消え、
`nav` も初期化画面（`init`）にリセットされる問題を修正する。

## 現在の動作（問題）

1. ユーザーがプロファイルを選択し、走行モードを選択して別の画面（例: 自動走行）にいる
2. F5を押してページをリロードする
3. 以下がリセットされる:
   - 現在のページ (`nav`) → `'init'` にリセット
   - 選択中プロファイル名 → `null` にリセット（右上から消える）
   - 選択中走行モード名 → `null` にリセット（右上から消える）

## 期待する動作

1. ページリロード後も以下が復元される:
   - 直前にいたページ（nav）
   - 選択中プロファイル名（右上表示）
   - 選択中走行モード名（右上表示）

## 技術的制約

- **プロファイルID**: `/api/v1/drive/status` APIがサーバー側の `active_profile_id` を返す（権威ある情報源）
- **プロファイル名**: APIから名前が取得できないため、IDから `/api/v1/profiles/{id}` を別途取得する必要がある
- **走行モード**: サーバー側に選択状態を保持する仕組みがない（フロントエンドのみのState）
- **nav（現在ページ）**: フロントエンドのみのState

## 解決方針

`localStorage` を使用してフロントエンド状態を永続化する:

| キー                | 保存内容              | 復元タイミング |
|--------------------|----------------------|--------------|
| `drv_nav`          | 現在のページ           | マウント時    |
| `drv_profile_id`   | 選択中プロファイルID   | マウント時    |
| `drv_profile_name` | 選択中プロファイル名   | マウント時    |
| `drv_mode_id`      | 選択中走行モードID     | マウント時    |
| `drv_mode_name`    | 選択中走行モード名     | マウント時    |

### API整合性

マウント時に `/api/v1/drive/status` でサーバー状態を確認:
- APIの `active_profile_id` が localStorage と異なる場合、APIを優先してプロファイル名を再取得
- APIに `active_profile_id` がない場合は、localStorage のプロファイル情報もクリア

## スコープ外

- サーバー側への走行モード選択状態の永続化（バックエンド変更なし）
- 他クライアントとのリアルタイム同期
