# 20261019 報酬で「1 発目の開度」（FF）を良くできるか — フィードバック誤差学習と MPC の位置づけ

**状態: 議論のまとめ（Claude.ai での議論 2026-10-19）。未決定・未実装。** 実装に入る前に、下の「決めること」をユーザーが決める。

## 1. 問い

偏差が小さいほど、またペダルの修正が少ないほど報酬を与えて、走るたびに FF（1 発目の開度）を良くしていけないか。

## 2. 結論

- 考え方は強化学習（RL）そのもの。ただし **実機の WLTP で RL をそのまま回すことはしない**。理由は 3 つ。
  1. **モード学習の禁止に当たる**（ユーザー決定 2026-10-14「モードの学習は不可」）。WLTP を走って報酬で学ぶと、時刻ごとの開度を覚えるだけになりやすい
  2. **試行回数が足りない**。RL は数百〜数千回の試行が要るが、実機は 1 本 30 分。さらに日内差で 1 本ごとに ±0.3〜0.5 km/h ぶれるので、報酬の差がノイズに埋もれる
  3. **報酬の形は MPC の評価関数と同じ**（偏差² ＋ ペダル変化²）。予測モデル（C8 の表）がすでにあるので、試行錯誤せずにその場で最適化できる
- 同じ狙いを、ルールの範囲でより早く実現する方法は 2 つ。
  - **A. フィードバック誤差学習**（本命）: 閉ループで走ったときの「マップの予測と実測の差」を、**時刻ではなく状態ごと**に貯めて、マップの補正表として残す
  - **B. MPC（全体計画の 2u）**: 「偏差 ＋ ペダル変化」の評価関数を毎周期その場で最適化する。報酬の最大化をオンラインで解くもの
- 順番は A → B。A で表が良くなるほど、MPC の予測も当たるようになるので、A の作業は B でも無駄にならない

## 4. A. フィードバック誤差学習の設計案

### 4.1 学習する量

各周期で、実際に出た加速度とマップの予測の差を取る（今の DOB と同じ量）。

```
r(t) = a_meas(t) − f(v(t), u(t − L))
```

- `f`: 今の C8 の表（戻しの表・発進側／停止側の表も含め、手順3 と同じ引き方）
- `u(t − L)`: 遅れ L 分前に実際に出した開度（DOB と同じ時刻合わせ）
- `L`: 手順2 で測ったペダル別の遅れ

DOB（C11）との違いは扱い方だけ。

| | DOB（C11） | フィードバック誤差学習 |
|---|---|---|
| r の持ち方 | 時間でならした **1 つの値**（ペダル別） | **マスごと**（車速の帯 × 開度 × ペダル（× 戻し量））に貯める |
| 直すもの | 日内差など、走行全体のずれ | マップの形のずれ（「この車速・この開度では毎回強い」など） |
| 寿命 | その走行の中だけ | 表として残り、次のモード走行で使う |

- 古典的なフィードバック誤差学習（川人）は FB の出力 u_fb を教師にする。今の構成では予測と実測の差 r が直接測れるので、r を使う
- **P の上乗せ（偏差 ÷ τ）は学習に使わない**。P は「目標からずれたから戻す」分で、マップの誤差ではない

### 4.2 更新式

マス k ごとに補正 c_k を持つ。1 つの行を周辺のマスへ補間の重み w_k で分ける（表を引くときと同じ重み）。

```
c_k ← c_k + η_k · w_k · ( r − d̂_共通 − c_k )
```

使うときは、補正した表を今までどおり逆に引く。

```
f'(v, u) = f(v, u) + c(v, u)
u_ff = invert_f'(v, 要る加速度)
```

- **d̂_共通 を引くのが要点**。その日の全体のずれ（日内差）は DOB の役目で、表には形のずれだけを残す。引かないと、学習した日の日内差まで表に焼き付き、別の日に逆効果になる
- d̂_共通 の候補: (a) その周期の DOB の推定（ペダル別） (b) 学習走行全体での r の平均（ペダル別）。**既定は (b)**（FB の種類に依らず成り立つため。4.4 参照）。(a) は FB に DOB があるときだけ選べる

### 4.3 係数と決まり（全車共通で持つ。値は仮）

| キー（案） | 役割 | 初期値の目安 |
|---|---|---|
| `fel.eta` | 学習率。`η_k = max(1 / n_k, eta_min)`（サンプル数で平均する形 ＋ 下限で忘却） | eta_min 0.01 |
| `fel.n_min` | このサンプル数（重みの合計）未満のマスは補正を使わない | 数十周期（数秒分） |
| `fel.c_max_kmhs` | 補正の上限（±） | 0.3〜0.5 km/h/s |
| `fel.common_offset` | d̂_共通 の取り方（`run_mean` / `dob`） | `run_mean`（既定案） |
| 更新を止める条件 | DOB（C11）と同じ: 停車保持・停車速度以下・ガバナー作動・最大開度・遅れ L の範囲内にペダル切替がある行 | 2q で見つけた抜け（`d799b26`・`c790f30`・`2284a09`）をそのまま流用 |
| 低速（7.5 km/h 未満）の扱い | DOB は使っていないが、停止前の減速は外れの最大の塊。学習走行で停止前の行を集めて、停止側の表の補正として持つかは決めること | 決めること |

- 補正表 c は pkl に別の配列として持ち（`fel_correction` など）、元の f は書き換えない。比べるとき・戻すときのため
- 補正表が無い pkl、または `fel.enabled: false` なら今と完全に同じ動き

### 4.4 運用のどこに入れるか

学習運転のあとに、**閉ループの学習走行（1b）** を足す。

```
0.  アクチュエータのキャリブレーション
1.  学習運転（G ランプ）             → マップ f を作る（今と同じ）
1b. 閉ループの学習走行（新規）       → その時点の FB で走り、r をマスごとに貯めて補正表 c を作る
2.  モード走行（KPI 判定）           → f + c を逆に引く。FB はそのまま（今なら C12）
```

1b の走行パターンの要件:

- **評価するモード（WLTP など）は使わない**（モード学習の禁止を守る）。毎回乱数で作る合成パターン（加速・定速・減速・停止を、いろいろな G と車速で並べたもの）にする。乱数の種はログに残す
- **今の FF が弱い場面を必ず含める**: 低速の緩い減速から停止まで／ブレーキの戻し／惰行からブレーキへの切替／発進直後／長い惰行
- 長さは 10〜15 分程度を目安に、モード走行で使うマスが n_min を超えるまで走る（足りないマスは表示して知らせる）
- 制御は**その時点の FB（候補は問わない）**。今なら C12 だが、今後より強い FB に置き換わっても 1b の設計は変えない。理由: r の u は FF・FB をすべて足した「実際に出した開度」なので、r は FB の種類に依らず「その開度でマップの予測とどれだけ違ったか」だけを表す。1b で FB に求めるのは (1) 合成パターンを安全に追従して狙った状態を通ること (2) 大きく外れて普段通らないマスにばかり行かないこと、の 2 つだけ
- FB を変えるときの注意:
  - d̂_共通 は FB に DOB がある前提にしない。既定は「学習走行全体の r の平均（ペダル別）」（4.2 の (b)）
  - FB 側が自分でマスごとの補正（オンライン学習など）を持つ場合は、学習中はそれを止めるか、その補正を f に含めて r を計算する（同じずれを 2 か所で直さない）

#### FF のみで走っても学習は成り立つ（FB ありを推す理由と、偏りの確かめ方）

r の式に FB は出てこない（要るのは「実際に出した開度」と「実際に出た加速度」だけ）。FF のみで走っても、各行の r はそのまま正しい学習データになる。違いは次のとおり。

| 観点 | FF のみ | FB あり |
|---|---|---|
| r の偏り | 出ない（開度が外乱に反応しない） | わずかに出る可能性がある。外乱で遅れると FB が深く踏むので、外乱の分が深い開度のマスに付きやすい（閉ループ同定の偏り） |
| 狙った場面を通れるか | 偏差が積み上がる（過去の FF のみの走行で最大 5〜6 km/h）。「停止前の緩い減速を 5 km/h 付近で」のような場面が、狙いとずれた車速・時刻で起きる | 基準に沿うので、狙った場面をほぼ狙いどおりに通る |
| 安全・範囲 | ずれが大きいと、学習していない範囲（範囲外のマス）に入りやすい | 範囲内に収まりやすい |

- **FB ありを推す**（Claude 意見）。1b の価値は、モードに近い場面（特に低速の停止前の減速）を狙った車速で通ることにあるため。偏りは、d̂_共通 を引くことと、外乱がゆっくり変わること（Tq 約 9 秒・日内差）から小さいと見ている（未確認）
- **偏りの確かめ方**: 同じ合成パターン（同じ乱数の種）を FF のみと FB ありで 1 本ずつ走り、それぞれで補正表 c を作って、マスごとの差を比べる。差が小さければ FB ありで確定。大きければ FF のみ、または弱い FB で学習する
- 確かめるのは 1b の実装後、最初の実機のとき（4.5 の机上確認では、手元の走行がすべて FB ありなので比べられない）

2 のモード走行中に表を更新し続ける（オンライン学習）こともできるが、**最初は入れない**。2q ① のように条件の抜けで値が積み上がると、その走行の中で被害が出る。まずは 1b でだけ学習し、2 では表を固定する。効果の検証もこの方がしやすい。

### 4.5 実装の前に確かめること（机上・走らない）

この方式が効くのは、**誤差が状態で決まり、走行をまたいで再現する場合だけ**。報告書には「停止側の表と実測の差が停車ごとに −0.01〜+0.99 km/h/s とばらつく」とある。このばらつきが状態（直前の減速の仕方・戻し量など）で説明できれば学習で直る。ランダムなら直らない。

確かめ方:

1. 同じモデル（`fwd_model_20261017_233210.pkl`）で走った 2 本（例: `142728` と `183428`）について、各行の r − d̂_共通 を計算する
2. マスごとに平均し、2 本の間でマスの値の相関（と、マスごとの差の大きさ）を見る。ブレーキ側・低速の停止前は別に集計する
3. 1 本目で作った補正表を 2 本目の行に当てて、予測誤差（r の絶対値の平均・p95）がどれだけ減るかを見る（交差検証）

判定の目安（決めること）: 2 本目の予測誤差がブレーキ側で 20% 以上減れば 1b を実装する。減らなければ A は見送り、B（MPC）か停止前の別の対策へ進む。

### 4.6 1b を実装した後の実機確認

- 比べる相手: 同じ日・近い時間帯の C12（補正表なし）。日内差があるので、1 本だけで判定しない
- 見るもの: p95・\|偏差\|>1 の秒数・最大逸脱（特に停止前の 3 件の型）・ブレーキ相の p95・往復の KPI（FF が良くなれば、FF の往復も減る見込み）
- 2 本目の 1b（補正表を作り直す）で表が収束していくか（マスの値の変化量）も記録する

## 5. B. MPC（2u）の位置づけ

- 「偏差 ＋ ペダル変化」を評価関数として毎周期最適化する。報酬の最大化をその場で解くもの
- 往復の KPI で FB のゲインを上げられない今の状況には、ペダル変化（Δu）の重みで滑らかさを直接選べる MPC が合う
- 予測に使うモデルは f + c（A の補正込み）＋ DOB の d̂（外乱項）。ペダルの種類は今の列で決め、開度の量だけを QP で解く（2p の議論のとおり）
- 着手の条件は全体計画のとおり（A のあと、残りが遅れ・切替の場面だと分かったとき）

## 6. 決めること（ユーザー）

1. A を進めるか（まず 4.5 の机上確認だけ行うか）
2. 1b の走行パターンを乱数の合成パターンにしてよいか。「FF は手順2 のデータだけ」という決まりを「手順2（G ランプ）＋ 1b（評価しないパターン）」に広げてよいか
3. d̂_共通 の取り方（既定案は走行全体の平均。DOB の推定にするか）
4. 低速（7.5 km/h 未満）の停止前を補正表の対象に入れるか
5. 4.5 の判定の目安（ブレーキ側で予測誤差 20% 減）

## 7. 取り下げた案（記録）

- **P の上乗せだけに LPF（0.5 Hz）を入れて、アクセル側の P を強める案**: ユーザー判断で取り下げ（2026-10-19）。机上の見込みは p95 0.77 → 約 0.64 km/h（c 12.5 相当・往復は KPI すれすれ）
- **CAN 車速のノイズが大きいという指摘**: Claude の計算ミス（実際の加減速を含めてノイズと数えた）。訂正済み。ノイズは小さい（3 章）
