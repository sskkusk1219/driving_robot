# 要求定義: 初期化ページの修正（ハードウェア動作とフロントエンド表示の連動）

## 背景・課題

初期化画面で「初期化を実行」ボタンを押した後、フロントエンドのステップ表示
（通信確認・アラームリセット・サーボON・原点復帰）が実際のハードウェア動作と
リンクしていない。

現状 `src/web/static/js/screens/init.js` の `stepStatus()` は経過時間ベースの
**疑似シミュレーション**（`doneAt = i * 1.5` 秒）でチェックを進めているだけで、
バックエンドの `RobotController.initialize()` が実行する実際のハード操作の
進捗とは無関係。

## 要求

1. ハードウェアの各初期化ステップが完了したら、フロントの対応する欄が
   チェック（✓）されるようにする。
   - 例: ハードで通信確認ができたら、フロントの「通信確認」欄をチェック。
2. 実行中のステップは「実行中（⟳）」、未実施は「—」で表示。
3. ステップでエラーが発生した場合はフロントに反映（✗）。
4. 原点復帰が正常終了済みでスキップされる場合は「スキップ」表示。

## 対象ステップ（フロント表示と実ハード操作の対応）

| key          | ラベル              | 実ハード操作 |
|--------------|---------------------|--------------|
| comm_brake   | 通信確認 (ブレーキ) | brake_driver.enable_modbus_control() |
| comm_accel   | 通信確認 (アクセル) | accel_driver.enable_modbus_control() |
| comm_can     | 通信確認 (CAN)      | can_reader.read_speed() |
| alarm_reset  | アラームリセット (両軸) | accel/brake_driver.reset_alarm() |
| servo_on     | サーボON (両軸)     | accel/brake_driver.servo_on() |
| home_return  | 原点復帰            | accel/brake_driver.home_return()（正常終了時はスキップ） |

## 非機能要求

- 既存の WebSocket リアルタイム配信（100ms 周期）を利用し、ポーリングを増やさない。
- 既存テストを壊さない。
- バックエンドの状態遷移ルールを変更しない。
