# 要求内容

## 概要

学習運転を、`docs/ideas/initial-requirements.md` の Phase 8 が定義する「固定の開度パターンを
開ループで順に実行し、その時の実車速を記録する」方式へ本番配線する。開始前のブレーキ保持と
確認ポップアップ、クリープ特性の計測（ブレーキ緩め）を含む。収集した連続走行ログから
Ridge 逆モデルを学習する現行アプローチ（Phase 9）は維持する。

## 背景

現在の学習運転（`POST /drive/learning/start` → `RobotController.start_learning_drive`）は、
連続基準速度プロファイルを **FF+PID 閉ループ**で追従する `build_learning_reference` + `DriveLoop`
方式で動いている。一方、Phase 8 が要求する**開ループの開度パターン方式**に対応する実装
（`LearningDriveManager.generate_patterns` / `run_pattern`）は存在するが、本番フローから
一切呼ばれずデッドコード化している。

逆モデルは「速度 → 開度」を学習するため、初回学習時（モデル・FF が無い状態）は、閉ループだと
「PID 単独でたまたま通った開度域」しかデータが取れない。開ループの開度パターンはコントローラに
依存せず開度軸を端から端まで励起できるため、白紙からのブートストラップに適する。

## 実装対象の機能

### 1. 開始フロー（確認ポップアップ＋ブレーキ保持）
- 学習開始ボタン押下で、走行前チェック（下記）を実施し、合格したら
  **車両プロファイルの停車中ブレーキ開度（`stop_brake_opening_pct`）までブレーキを踏み込み**、
  「学習運転を開始しますか?」の確認ポップアップを表示する
- ユーザーが「はい」→ 学習運転を開始（ログ記録開始）
- ユーザーが「いいえ」→ ブレーキをリリースして終了（READY へ戻る）

### 2. 走行前チェックの拡張
- 既存6項目に加え、**車速が 0 であること**を確認項目に追加する（走行中の学習開始を防止）

### 3. クリープ特性の計測（ブレーキ緩めフェーズ）
- ブレーキ保持（`stop_brake_opening_pct`）から**少しずつブレーキを離していき**、
  クリープ車速とクリープ加速率を計測する
- 学習終了後、計測したクリープ車速（`creep_speed_kmh`）とクリープ加速率（`creep_rate_kmhs`）を
  車両プロファイルに反映する（既存の自動学習 `train` 経路の `estimate_dynamics_params` が
  連続ログから推定・反映する）

### 4. 開度スイープのパターン生成
- プロファイル最大開度でスケールした固定開度パターン列を生成する（Phase 8 の例に倣う）
  - アクセルスイープ（brake=0、段階的に〜`max_accel_opening`）
  - ブレーキスイープ（accel=0、走行中から段階的に〜`max_brake_opening`）
- 最大開度を超えるパターンは生成時に除外する

### 5. 開ループ実行ループ（連続ログ記録＋スキップ型安全）
- 各パターンの固定開度を指令し、走行全体を 100ms 周期で**連続した1本の (実車速, 開度) 軌跡**として
  `drive_logs` に記録する（クリープ緩め・パターン間原点復帰の過程も連続記録）
- **過速度・過G時は非常停止せず、当該パターンの測定を打ち切って次の開度へ進む**
  - 過速度: `actual_speed > profile.max_speed`
  - 過G: 実測加速度の絶対値が `profile.max_decel_g` を超過（**設定上限Gは加速・減速で
    同一**のため、加速側・減速側の両方に同じ上限を適用する）
  - **`max_speed` / `max_decel_g` は車両プロファイルから参照する**
- **過電流・CAN 断・サイクル例外は従来どおり非常停止**に倒す
- 全体を 20 分以内に収める

### 6. 学習運転フローへの配線
- 開始フロー（arm）→ 確認 → 実行ループ → 完了で RUNNING→READY、非常停止で安全停止
- 完了後に既存の自動学習（`POST /drive/learning/train`）が連続ログから逆モデルを生成し、
  クリープ等の物理定数とともにプロファイルへ反映

## 受け入れ条件

### 開始フロー
- [ ] 開始ボタンで走行前チェックが走り、合格時のみブレーキを `stop_brake_opening_pct` まで踏む
- [ ] 確認ポップアップ「はい」で学習開始（ログ記録が始まる）
- [ ] 確認ポップアップ「いいえ」でブレーキをリリースし READY へ戻る

### 走行前チェック
- [ ] 車速 ≠ 0 のとき走行前チェックが NG になり学習を開始できない

### クリープ計測
- [ ] ブレーキ緩めフェーズが連続ログに記録される
- [ ] 学習終了後にクリープ車速・クリープ加速率がプロファイルへ反映される

### 開度スイープ／実行ループ
- [ ] `max_accel_opening` / `max_brake_opening` を超える開度が含まれない
- [ ] 各サイクルで連続時系列が `drive_logs` に記録される
- [ ] 過速度・過G時は非常停止せず次の開度へ進む（`max_speed`/`max_decel_g` はプロファイル参照）
- [ ] 過電流・CAN 例外では `on_emergency` が発火し安全停止する
- [ ] 正常完了で `on_complete` が一度だけ呼ばれ RUNNING→READY 遷移する
- [ ] `current_accel_opening` / `current_brake_opening` を公開しライブ開度表示が動く

### 学習運転フロー
- [ ] start → 連続ログ蓄積 → `train` で逆モデル生成・プロファイル紐づけ（スタブ構成で確認）

## 成功指標

- 実機シャシダイナモで学習運転が 20 分以内に完了する
- 開ループ収集の連続ログから初回逆モデルとクリープ等の物理定数が生成され、プロファイルに反映される

## スコープ外

- `autoTrain` の学習対象ログ絞り込み（run_type='learning' / 期間限定）。別タスクで検討
- UI 表示 MAE の in-sample 問題（hold-out 評価・ラベル明示）。別タスクで検討
- 2 段階方式（開度パターンで初期学習 → G パターンで再学習）。今回は開度パターン単独

## 追加要求（2026-06-18）: 連続走行への再構成と緩やか踏み込み

### 背景

実機検証の結果、現行はアクセルスイープ（純アクセル）とブレーキスイープ（SPINUP→ブレーキ）を
**完全に別々**に回しており、ブレーキ用の人工的な SPINUP（固定30%アクセル）や、アクセル終わりの
固定30%RETURN が時間・データの無駄になっていた（20分budget の主因）。また MEASURE フェーズは
目標開度を**一気に**指令しており、踏んだ瞬間に低速＝高加速で過Gスキップに掛かりやすく、実運転とも
乖離していた。

### 実装対象（§4「開度スイープ」・§5「実行ループ」を以下で更新する）

#### 7. アクセル→ブレーキの連続走行への再構成（ACCEL/BRAKE スイープを統合）

- 1サイクルを **「アクセルで加速 → アクセルを離す → ブレーキを印加 → 停車」** の連続走行にする
- 走行パターンは **(accel_opening, brake_opening) のペア**を持つ単一種別 `COMBINED` に統合する
  - 旧 `ACCEL` / `BRAKE` の別建てスイープを廃止
  - **SPINUP（固定30%事前加速）と固定30%RETURN を廃止**（直前のアクセル加速が助走、ブレーキ印加が停車を兼ねる）
- 開度ペアは **アクセルスイープ列とブレーキスイープ列を zip**（短い方は巡回）して生成する
  - 例: (2,2)(4,4)…(max_accel, max_brake)。全 accel 値・全 brake 値が最低1回は現れること
- アクセル区間は brake=0（純アクセル）、ブレーキ区間は accel=0（純ブレーキ）で、片軸ずつ
  クリーンなサンプルになる（逆モデル特徴量は実車速由来のため連続軌跡でも成立）
- **CREEP / CREEP_SETTLE は現状維持**（クリープ解放・安定待ち・クリープ定数計測はそのまま）

#### 8. 緩やかな踏み込み（ランプ）

- アクセル・ブレーキとも、目標開度へ **`ramp_time_s` 秒かけて線形に到達**させる
  （`opening(t) = target × min(1, t / ramp_time_s)`）。いきなり目標開度を指令しない
- `ramp_time_s` は config 化し、実機で適合できるようにする（アクセル/ブレーキで別々に持てる）
- ランプにより踏み始めの加速度が抑えられ、過Gスキップに掛かりにくくなる（副次効果）

### 受け入れ条件（追加）

- [ ] `generate_patterns` が CREEP / CREEP_SETTLE / COMBINED を生成し、COMBINED は accel/brake の
      zip ペア（短い方は巡回）で全開度値を網羅する。SPINUP/固定RETURN 種別は生成されない
- [ ] 1サイクルで「アクセル加速→アクセル解放→ブレーキ減速→停車」が連続ログに記録される
- [ ] アクセル・ブレーキとも `ramp_time_s` で 0→目標へ線形に踏み込む（一気指令でない）
- [ ] `ramp_time_s` は config で調整できる（factory デフォルト＋生成箇所で上書き可）
- [ ] 過速度・過G スキップ（デバウンス、`max_speed`/`max_decel_g` 参照）は維持される
- [ ] 過電流・CAN 例外で `on_emergency`、正常完了で `on_complete` が一度だけ（従来どおり）
- [ ] 20分以内に収まる（SPINUP/RETURN 廃止と統合で短縮）

### スコープ外（追加分）

- ramp_time_s の最適値そのものの確定（実機適合でユーザーが詰める）
- accel/brake 開度ペアリング戦略の高度化（今回は素直な zip）
