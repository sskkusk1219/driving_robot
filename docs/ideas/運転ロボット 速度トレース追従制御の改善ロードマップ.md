# 運転ロボット 速度トレース追従制御の改善ロードマップ

Oct 17, 2026 · @佐々木　康介

FF はもう限界近くまで詰められており、今の主な誤差は車両側の遅いずれ（⑥ で偏差の平均 +1.62 km/h、外れの 95% が速い側）です。次に入れるのは、加速度の次元で入れる外乱推定（DOB）か積分です。その後に惰行区間のペダル調停、安定限界の実測による τ の決め直し、遅れの予測器を入れ、MPC は最後にします。

## 背景とKPI

- 対象：シャシダイナモ上で、運転ロボット（Raspberry Pi 5）が規定パターン（WLTP など）を走行する。
- KPI：|偏差| の max が 1 km/h、p95 が 0.4 km/h。KPI は FB 込みで達成し、FF は手順2 のデータだけで詰める（モードの学習は不可。決定 2026-10-14）。
- 現状：C8（順モデル「車速 × 開度 → 加速度」を逆に引く FF）に、遅れの実測値・先置き・戻り待ち・安全網まで入っている。⑥ `142637` は最大 6.62・p95 4.36 km/h、同時踏み 0 秒、ペダル往復 0.28・0.58 回/s（合格）。
- 進行中：C10（偏差/τ を要る加速度に足して表を引き直す、τ = c × 遅れ、c = 100）。⑦ 案A・⑧ 案B が実機待ち。
- 前回案からの修正：遅れのプレビュー・不感帯補償・切替ロジックは実装済みなので外した。ILC はモード学習の禁止に反するので外した。

数値は ProblemReport\_20261001 と fwd\_model\_20261017\_022008.pkl から取っています。

| 誤差の源 | 根拠 | 効く手段 |
| --- | --- | --- |
| 車両側の遅いずれ（日内差） | 同じ指令でも日によって最大 6.4 km/h 違う。偏差の平均が +0.20 → +0.90 → +1.62 km/h と進んでいる（④→⑤→⑥） | 積分または DOB |

p95 0.4 km/h は、0.2 Hz より遅い成分をほぼ消せれば届く計算です。max 1.0 km/h はブレーキの踏み始め・戻しや発進といった場面で決まるので、いちばん難しい KPI です。

## 取り入れる制御と順番

### ① ⑦・⑧（C10 の案A・案B）はそのまま走る

P の上乗せの形を確かめる段階なので、予定どおりで問題ありません。走るときに、②で使う「実加速度 − マップの予測加速度」を CSV に出しておくと、日内差の大きさを直接見られます。

### ② 積分を DOB の形で入れる（最優先）

```latex
a_{cmd} = a_{ref} - \hat{d} + \frac{v_{ref} - v}{\tau}
```

```latex
\hat{d} = \mathrm{LPF}\left[ a_{meas} - \mathrm{map}\left(v,\ u_{\text{実開度}}(t - L)\right) \right]
```

- 日内差は、加速度に乗った一定の外乱として表れます。P だけだと偏差が残りますが、積分か DOB なら定常の偏差を 0 にできます。
- 積分ではなく DOB の形をすすめるのは、惰行中や停車前後でも外乱を推定し続けられるからです。d̂ の値自体が「今日の車のずれ」なので、診断にも使えます。
- 必須の付帯処理：ペダルが min や最大開度に張り付いている間と停車中は更新を止める。発進側の行は除外する。LPF の時定数は数秒〜十数秒。
- 判定：偏差の平均が ±0.2 km/h 以内に入り、|偏差|>1 の秒数が大きく減ること。

### ③ 惰行区間のペダル調停（EV 回生のルールとまとめて）

②を入れると、惰行中に「速すぎるのに何もしない」区間が誤差として目立ってきます。

- 速すぎる側に一定以上ずれたら浅いブレーキ、遅すぎる側なら浅いアクセルを入れる。
- ヒステリシスと最短保持時間を付ける。
- 「アクセル → ブレーキは惰行を X 秒以上」の決まりと、2o-9 の戻り待ちを守る。

すでに決めてある「PID の段のペダル調停」を、ここで前倒しで入れるイメージです。

### ④ 安定限界を一度測って、τ（c）を決め直す

c = 100 は、線形の理屈から見るとかなり慎重すぎます。

- 遅れ L だけのループ（e^(−sL)/(τs)、L = 0.27 s）で考えると、τ = 1 s でも位相余裕は約75°、ゲイン余裕は約15 dB あります。前の車の加振で −180° が 1.1〜1.2 Hz だったのは、遅れ 0.22 s 程度とよく合います。
- 一方、C5 は c = 13〜24 で約 0.3 Hz の揺れが出ました。これは遅れだけでは説明できません。不感帯をまたぐこと、ペダル切替、車速信号の段差などが原因の候補です。C10 は「踏んでいるペダルの中だけ・min で止める」形なので、この原因がなくなっている可能性があります。
- c を 1 本ずつ半分にする方法は、1 本 30 分かかり日内差も混ざるので、結論までに時間がかかります。代わりに、定速（30・60・90 km/h）で a\_cmd に正弦波または PRBS を足し、C10 の形のままループの周波数応答を 1 本で測ります。そのうえでゲイン余裕 6 dB・位相余裕 45° 程度から τ を決めます。見立てでは、τ は数秒程度まで下げられます。

### ⑤ 遅れの予測器（スミス予測器の簡易版）＋車速のフィルタ

- v̂(t+L) = v(t) + ∫ map(v, 直近 L 秒の指令) dt として、e = v\_ref(t+L) − v̂(t+L) で補正量を計算します。今あるマップだけで作れ、モデルが合っている範囲で遅れの上限を押し上げられます。
- 2o-4 では CAN 車速の段差状の跳び（263 回）が出ていました。FB を強めると、この跳びがペダルの往復に直結します。指令から予測した加速度を使うカルマンフィルタで車速を滑らかにし、②の a\_meas もここから取ります。
- 段3（基準の平滑化）も、FB が入って往復が増えたときにここで合わせて入れます。

### ⑥ MPC（それでも max 1.0 が残った場合）

P → PI で足りず、残りが遅れや切替の場面だと分かったときに着手します。②の d̂ を外乱項としてモデルに入れ、ペダルの種類は今の列で決め、開度の量だけを QP で解く形が素直です。

## 入れないもの

- **ILC**：モード学習の禁止に反する。主な誤差は日内差なので、ラップ間の学習はもともと効きにくい。
- **LQR**：今の状態の取り方では P・PI と同じ答えになる。
- **D 項**：車速信号の跳びと遅れのせいで、ペダルの往復が増えるだけになりやすい。
- **マップのセルの逐次更新**：②の DOB が同じ役割を担う。入れるなら②の後で、手順2 のデータの範囲内に限る。
