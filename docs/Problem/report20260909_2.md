## 2. 根本原因① FOPDT 同定が構造的に成立していない【最重要】

`src/domain/pid_tuning.py:161 identify_fopdt` は「アクセル一定保持 → 車速プラトー」を前提に
`k = rise / held`（同 :111）で定常ゲインを求める。学習運転 `0e7d9770` を全区間検証した結果、
**アクセル保持 17 区間すべてでプラトーに達していない**。

**同じ車で k が 15 倍ばらつき、区間長にほぼ比例する。** 採用された中央値 3.5115 は物理量ではない。
120km/h 上限の本システムでは真のプラトー（終端速度）に達する学習運転は原理的に組めないため、
FOPDT を同定し直すのではなく**モデル構造を替える**必要がある。

### この k が決めていた 4 か所

| 波及先 | 定義場所 | 旧値 | 影響 |
|---|---|---|---|
| ロバストゲイン上限 `kp_robust = τ/(k·θ·2)` | `trim.py:90` | **0.80 %/(km/h)** | FB 権限が 3〜4 倍不足 |
| ゲインスケジュール基準 `g_nominal = τ/k` | `drive_loop.py:200` | 0.80 %/(km/h/s) | 実ペダルゲイン逆数 0.94〜4.5 と不整合 |
| ILC 学習ゲイン `L = 0.25/k` | `plan_update.py:63` | **0.071 %/(km/h)** | 誤差 4km/h でプラン補正 0.28%＝ほぼ学習しない |
| ILC リード `Δ = θ + 0.5τ` | `plan_update.py:70` | 1.905 s | τ が無効なので根拠がない |

### 正しいプラント構造

実車は「ペダル開度 → 加速度」が静的（＝同定済みペダルゲイン `k'(v)`）で、車速はその積分。
すなわち **積分系＋むだ時間** `G(s) = k'·e^(−θs)/s`。SIMC（Skogestad）の積分系整定則は

```
Kc = 1 / (k'(v)·(θ + τc)),   Ti = 4(θ + τc),   τc = 1.5·θ
```

θ（むだ時間）は「区間開始→車速が 0.3km/h 上昇するまで」で測っており、プラトー到達を前提と
しないため**引き続き有効**（実機 0.500s）。

## 4. 根本原因③ プランのゼロ位相ローパスがコーナーを前後ににじませる

`zero_phase_lowpass`（forward-backward の 1 次 IIR）は位相遅れ 0 の代わりに**非因果**で、
コーナーを前後に対称ににじませる。0.25Hz は RC = 1/(2π·0.25) = 0.64s を両方向に掛けるため、
実効的に前後 ~1.3s の「先食い」が出る。

実測（`__verify_pattern__` + 実機プロファイル、解析 effort に対する保持率）:

| 区間 | 旧 0.25Hz | 新 1.0Hz |
|---|---|---|
| 減速コーナー t=79-83s | 76.6% | **89.1%** |
| 軌跡頂点 t=143-147s | 77.7% | **89.0%** |
| 全区間平均 | 88.4% | 89.6% |

全区間平均がほとんど変わらないのが正しい（大半はランプで、にじみが問題になるのはコーナーだけ）。

t=82.0s の生値: 解析 −5.16% に対し旧プラン −4.00%（＝ブレーキ不感帯の床まで抜けていた）。

**`PLAN_ACCEL_SMOOTH_S`（1.0s のセンタリング移動平均）は当初「にじみの一因」と見たが、
閉ループ模擬で 1.0 のほうが一貫して良く、据え置いた**（全 12 通りの組み合わせで同傾向）。
にじみはローパスがほぼ全てだった。センタリング窓は位相遅れが無く、フェーズ分類を安定させる
効果のほうが大きい。

## 5. 根本原因④ むだ時間 0.5s に対し FF の位相補償がゼロ

旧実装のプラン参照は `effort_at(elapsed_s)` / `phase_at(elapsed_s)` で**時間シフト 0**。
基準軌跡の要求加速度がステップ変化するコーナー（t=146s で +2.0 → −5.0 km/h/s ＝ 7km/h/s の段差）
では、ペダルが θ 秒遅れて効くぶん **7 × 0.5 = 3.5km/h** の誤差が原理的に発生する
（実測ピーク −4.21km/h と整合）。フィードバックは誤差が出てからしか動けないので、
ゲインをいくら上げてもこの成分は消えない。

**`pid_preview_s` とは別物。** あちらは PID が見る基準速度を前倒しするもので、ランプ追従中に
定常偏差を作る。模擬で 0.0→0.8s のとき p95 が 1.13 → 3.67 と悪化するため **0.0 のまま据え置く**。

## 6. 根本原因⑤ 保存プランがプロファイル再同定と切り離されている

`pedal_plans` の STOP_HOLD effort は**一律 −16.0%**、現行プロファイルの
`stop_brake_opening_pct` は **24.0%**。`plan_service.prepare()` は保存プランを無検証で返していた。

結果、基準 0km/h に対し実車速 1.75km/h のクリープが 6.3 秒続いた（t=114.6-120.9）。

### 「制御と車両プロファイルが紐づけられているか」への回答

**一部切れている。**

- 保存プランは学習サイクル・モデル再学習をまたいで持続する（設計どおり）。今回のプランは
  `iteration=6` で、**前日のサイクル 3ca20d43 の反復 1-3 と今回の 4-6 が連続している**。
  一方でプロファイルの物理定数は学習運転のたびに再同定されるが、両者を突き合わせる経路が
  無かった。
- `pedal_plans` に**存在するのは検証モード 1 件のみ**。本番モード（WLTP 等）の保存プランは
  1 件も無く、本番走行は毎回 FF 由来プランから始まる状態。
- FF モデル（`model_path`）とプロファイルは紐づいている。惰行カーブ・ペダルゲイン・不感帯・
  クリープ・停止保持は `feedforward_params` に、FOPDT は `dynamics_params` に保存され、
  制御が参照している。

## 8. 仕様書（`docs/manuals`）との突き合わせ

### 8-1. ペダルが「パチン」と動く原因は速度ではなく加減速度だった

run1 の全サイクルについて、ストローク実測（accel 6674 / brake 5145 pulse = 66.7 / 51.5mm）と
`_DEFAULT_SPEED_MM_S=100` / `_DEFAULT_ACCEL=30`(0.3G) から移動プロファイルを計算した。

| 軸 | 1 サイクル移動量 中央値 / p95 / max | 所要時間 中央値 | **50ms 中の稼働率** |
|---|---|---|---|
| accel | 0.082 / 0.215 / 0.630 mm | 10.6 ms | **中央値 21.1%** |
| brake | 0.040 / 0.181 / 2.244 mm | 7.4 ms | **中央値 14.7%** |

**アクチュエータは毎サイクルの 79〜85% を停止して過ごしていた**＝20Hz の階段動作。

「距離 ÷ 時間」で VCMD を決める方式は**成立しない**: 必要速度は中央値 1.6 / 0.8 mm/s で、
**97〜99.7% が最低速度（リード長÷0.8。リード10 で 12.5mm/s）を下回る**。
RCP6-ROD 仕様「最低速度以下の速度は設定しないでください。設定した速度では動きません」に抵触し、
ペダルがまったく動かなくなる。

**真因は加速度律速。** 100mm/s・0.3G の三角プロファイル境界は 3.4mm だが、走行中の最大移動量は
accel 0.63 / brake 2.24mm。全移動が三角プロファイル＝**`_DEFAULT_SPEED_MM_S=100` は走行中に
一度も binding していない**。動作を「パチン」にしていたのは `_DEFAULT_ACCEL=30`（ACMD 最小値 1 の 30 倍）。

対策: 三角プロファイル `t = 2√(d/a)` より `a = 4d/T²`、`ACMD = clamp(a/0.01G, 1, 30)`。
T は制御周期の 0.8 倍（40ms）。

### 8-4. アクチュエータ型式の確定（レポート作成後の追記）

ユーザーが実機ラベルを確認し `docs/hardware.md` に記載。仕様書（MJ3751-2Q）から展開した値を
`config/settings.toml` の `[actuator.accel]` / `[actuator.brake]` に記録した。

| 項目 | アクセル `RCP6-RA6R-WA-42P-6-100-P3-M-MT` | ブレーキ `RCP6-RA7R-WA-56P-8-100-P3-M-ML` |
|---|---|---|
| **リード長** | **6 mm** | **8 mm** |
| ストローク | 100 mm | 100 mm |
| **最低速度**（リード÷0.8） | **7.5 mm/s** | **10.0 mm/s** |
| 最高速度（高出力設定 有効／無効） | 450 / 250 mm/s | 水平420・垂直350 / 210 mm/s |

- **`_DEFAULT_SPEED_MM_S = 100` は仕様上そのまま安全**だった。最も保守的な組合せ

- **`_MIN_TIMED_SPEED_MM_S = 12.5` は保守的すぎた**。リード 10mm を仮定した暫定値で、実機は

  高出力設定無効時の上限列 0.7G まで余地はあるが、本ラウンドの変更方向は微小移動で ACMD を
  **下げる**側（`acmd_for_move`）なので上げない。
