# 要求内容

## 概要

自動走行制御方式のコードレビュー(2026-06-11 実施)で確定した欠陥 10 件と残課題 6 件を修正し、
product-requirements.md のプライマリー KPI(車速追従精度・振動抑制・連続走行)を満たせる制御アーキテクチャに改修する。

## 背景

レビューの結論: 「Ridge 逆モデル FF + PID 補助 + クリープ定数化」という方式自体は妥当だが、
**FF と PID の合成・調停層に構造的な欠陥**があり、ゲイン調整では以下のプライマリー KPI に到達できない。

- 車速追従精度(通常): 速度偏差絶対値の 95 パーセンタイルが 0.2km/h 以内
- 車速追従精度(最大逸脱): 速度偏差絶対値が 1.0km/h を超えない(例外なし)
- 振動抑制: 速度偏差の符号反転が 5 秒に 1 回以下
- 連続走行時間: エラー・人的介入なしで 10 時間以上

## 実装対象の機能

### 1. ペダル調停コンポーネント(PedalArbiter)の新設

- FF と PID を符号付き単一「努力量」(+: アクセル%, −: ブレーキ%)に合成してからペダルへ写像する
- 同時踏み禁止を事後の消去ルールではなく構造として保証する(常にどちらか一方のみ非ゼロ)
- 切替ヒステリシス・アクセル再踏込ディレイ・ペダルレートリミット・不感帯逆補償を一箇所で実施
- プロファイル最大開度クランプと飽和フラグ(アンチワインドアップ用)を提供

### 2. フィードフォワードの連続化

- predict を符号付き努力量を返す形に変更し、レジーム境界(dv_1.0≈0)をブレンドバンドで連続化
- 停車保持ブレーキの解除判定を最短ホライズン(0.5 秒先)に変更
- クリープ則を加速要求 [0, creep_rate] のみに限定し、クリープ速度未満の減速要求ではブレーキを残す
- エンジンブレーキ則(惰行)を v0 ≥ creep_speed の場合のみに限定
- 不感帯スナップを FF から削除(調停層へ移動)

### 3. PID の強化

- 計測 dt による更新(サイクルスキップ時の微分スパイク防止)
- 出力制限と条件付き積分(飽和方向への積分停止)+積分量クランプによるアンチワインドアップ

### 4. KPI ランタイムモニタの新設

- 走行中に最大偏差・偏差ヒストグラム(P95 算出)・符号反転回数(任意 5 秒窓の最大)を集計
- 1.0km/h ハード上限超過を即時 warning ログ
- 走行終了時にサマリをログ出力し、コントローラから参照可能にする

### 5. 安全経路・タイミングの修正

- CAN 車速鮮度上限を 1.0 秒 → 0.2 秒(設定可能)に引き締め
- emergency_stop / 各 stop で飛行中サイクルを停止完了待ち(stop_and_join)してから原点復帰
- DriveLoop 内部起因の非常停止を SafetyMonitor.trigger_emergency 経由に統一
- サイクル未完了が 1 秒続いた場合のウォッチドッグ非常停止
- get_realtime_data のキャッシュ鮮度チェック(古いキャッシュでの障害マスキング防止)

### 6. プロファイル・モデル整合

- select_profile で FF モデルを必ずアンロードしてから条件付きロード
- /learning/train 成功時にアクティブプロファイルの in-memory 状態(モデル・物理定数)を更新

### 7. 10 時間連続稼働の堅牢化

- ログ書き込み保留タスク数に上限を設け、超過時はログをスキップして走行を優先
- WS broadcast をタイムアウト付き並列送信に変更

### 8. 追加定数(ユーザー要望: 制御チューニング定数の整備)

FeedforwardParams(車両プロファイル別、JSONB 永続化)に以下を追加:

- `switch_hysteresis_pct`: ペダル切替ヒステリシス(既定 0.5%)
- `accel_reengage_dwell_s`: ブレーキ後のアクセル再踏込ディレイ(既定 0.3 秒)— ブレーキ側は安全上ディレイなし
- `accel_rate_limit_pct_s` / `brake_rate_limit_pct_s`: ペダル開度レートリミット(既定 200 / 300 %/s)
- `pid_output_limit_pct`: PID 出力権限上限(既定 50%)

## 受け入れ条件

### ペダル調停
- [ ] アクセルとブレーキが同時に非ゼロになる出力経路が存在しない(ユニットテストで網羅)
- [ ] FF ブレーキ中に微小正の PID 出力が入ってもブレーキが解除されない(ヒステリシス内)
- [ ] FF アクセル中に PID が減速を要求した場合、努力量合成によりアクセルが減る/ブレーキに切り替わる
- [ ] 最終指令が不感帯内に落ちる場合は 0 または不感帯以上に写像される

### FF 連続化
- [ ] dv_1.0 が ±ブレンドバンド内で出力が連続(境界テスト)
- [ ] 停車保持ブレーキが ref(t+0.5s) ≤ 0.5km/h の間維持される
- [ ] 低速(クリープ速度未満)の減速要求でブレーキ予測が 0 にされない

### PID
- [ ] 飽和方向の誤差では積分が増えない(条件付き積分テスト)
- [ ] dt を渡した場合に微分・積分が計測 dt で計算される

### KPI モニタ
- [ ] P95・最大偏差・5 秒窓最大符号反転数が既知系列で正しく算出される
- [ ] 1.0km/h 超過で warning ログが出る

### 安全経路
- [ ] read_speed が 0.2 秒超の古さで TimeoutError を送出する
- [ ] emergency_stop が飛行中サイクルの完了/キャンセルを待ってから home_return する
- [ ] DriveLoop 内部非常停止で SafetyMonitor の登録コールバックが発火する
- [ ] サイクル未完了 1 秒継続で非常停止が起動する

### プロファイル整合
- [ ] model_path なしプロファイル選択後に has_model が False になる
- [ ] /learning/train 成功後、アクティブプロファイルなら FF モデル・物理定数が即時反映される

### 品質
- [ ] 全ユニットテストがパスする
- [ ] ruff format / ruff check / 型チェックがパスする

## 成功指標

- レビュー指摘 16 件すべてに対応するコード変更とテストが存在する
- 制御経路(FF→調停→アクチュエータ)のどの組み合わせでも KPI を構造的に破る経路(減速権限喪失・バンバン・ワインドアップ・不連続)が存在しない

## スコープ外

以下はこのフェーズでは実装しません:

- KPI サマリの DB 永続化と GUI 表示(ログ出力とコントローラ属性公開まで)
- sklearn Ridge.predict の係数抽出による高速化(50ms 予算内で動作しており効率最適化は別タスク)
- LogWriter のバッチ INSERT 化(保留タスク上限で 10h 連続稼働は担保)
- 学習時のレジーム分割・特徴量設計の変更(モデル再学習が必要になるため。推論側のブレンドで対応)
- learning_drive.py の未使用コード(run_pattern)の削除(レビューで本番経路外と確認済み)
