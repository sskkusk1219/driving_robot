# プロダクト要求定義書 (Product Requirements Document)

## プロダクト概要

### 名称
**driving_robot** - シャシダイナモ向け自動運転ロボットシステム

### プロダクトコンセプト
- **高精度な車速トレース**: フィードフォワード＋フィードバック制御により、基準車速に対して±0.2km/h以内の精度で追従
- **人の運転からの脱却**: WLTPなどの運転サイクルをロボットが代替し、疲労・ばらつきのない長時間走行を実現
- **シンプルで拡張性の高いシステム**: 直感的なWeb GUIと充実したAPIにより、初心者から上級エンジニアまで対応

### プロダクトビジョン
シャシダイナモ試験における人的要因によるばらつきをなくし、誰でも・いつでも・再現性の高い走行試験を実現する。
アクチュエータ制御・運転モデル学習・リアルタイムモニタリングを統合したシステムにより、実験エンジニアが運転に費やしていた時間をデータ分析や実験設計に充てられるようにする。
またAPIと拡張インターフェースを提供することで、シャシダイナモ・計測器との連携を容易にし、実験手法開発エンジニアの研究活動を加速する。

### 目的
- WLTPなどの運転サイクルを再現性高く自動走行する
- 10時間以上の連続走行を無人で実現する
- 車両ごとの運転モデルを学習・蓄積し、精度を継続的に改善する
- シャシダイナモ・計測器との外部連携を可能にするAPIを提供する

## ターゲットユーザー

### ペルソナ1: 実験エンジニア（プライマリー）
- **年齢**: 25〜50歳
- **職業**: 自動車メーカーや研究機関の実験エンジニア
- **経験**: シャシダイナモでの走行試験経験あり、運転ロボットの操作は初めて
- **現在の課題**:
  - 毎日同じ運転サイクルを繰り返すことによる疲労とばらつき
  - 運転ロボットの操作が複雑そうで導入に不安
  - 運転に時間を取られ、実験準備やデータ分析が後回しになる
- **期待する解決策**:
  - 説明書なしでも走行開始できるシンプルなGUI
  - 正確なアクセル・ブレーキ制御
  - 走行中のリアルタイムモニタリングとログ取得
- **典型的なワークフロー**:
  1. 車両をシャシダイナモにセット
  2. PCのブラウザでGUIを開く
  3. 車両プロファイルを選択・キャリブレーション実施
  4. 走行モードを選択して実行
  5. モニタリングしながらデータ分析の準備

### ペルソナ2: 実験手法開発エンジニア（セカンダリー）
- **年齢**: 25〜50歳
- **職業**: 実験手法を開発するエンジニア
- **経験**: 機械設計・制御・プログラミングの有識者
- **現在の課題**:
  - 運転ロボットのカスタマイズ性が低く実験手法の開発に制約がある
  - 運転ロボット・シャシダイナモ・計測器の連携に手間がかかる
- **期待する解決策**:
  - 外部システムから制御できるAPI
  - リアルタイムモニタリングと柔軟な制御インターフェース
  - 充実したドキュメント

## 成功指標(KPI)

### プライマリーKPI（Must）
- **車速追従精度（通常）**: 全走行モード実行中の速度偏差（実車速 − 基準車速）絶対値の95パーセンタイルが0.2km/h以内であること
- **車速追従精度（最大逸脱）**: 全走行区間において速度偏差の絶対値が1.0km/hを超えないこと（例外なし）
- **振動抑制**: 全走行区間（加減速含む）において速度偏差の符号反転が5秒に1回以下であること（開発中に調整）
- **連続走行時間**: エラー・人的介入なしで10時間以上継続稼働できること
- **操作習得時間**: シャシダイナモ操作経験者が初めての操作で「プロファイル選択→キャリブレーション→走行開始」を15分以内に完了できること

### セカンダリーKPI（Should）
- **カスタマイズ性**: PIDゲイン・追従逸脱閾値・最大開度をGUIから変更できること
- **API提供**: 外部システムからロボットを制御・データ取得できるAPIが提供されていること

## 機能要件

### コア機能（MVP）

#### 1. 車両プロファイル管理

**ユーザーストーリー**:
実験エンジニアとして、複数の車両を扱うために、車両ごとのキャリブレーションデータと運転モデルをプロファイルとして保存・切り替えたい

**受け入れ条件**:
- [ ] プロファイル名を入力して新規作成・保存できる
- [ ] 作成済みプロファイルを一覧から選択して読み込める
- [ ] PIDゲイン・最大開度・最高車速・停止処理設定をプロファイルに保存できる
- [ ] キャリブレーションデータ（min/max位置）がプロファイルに紐づく
- [ ] 運転モデルがプロファイルに紐づく

**優先度**: P0（必須）

---

#### 2. キャリブレーション

**ユーザーストーリー**:
実験エンジニアとして、正確なペダル制御のために、アクセル・ブレーキのゼロフル位置を手動ジョグ操作で設定したい

**受け入れ条件**:
- [ ] アクセル・ブレーキともにジョグ操作でゼロ/フル位置を手動設定できる
- [ ] キャリブレーション中は最大開度設定を無視して全ストロークを設定できる
- [ ] バリデーション（ストローク妥当性・ゼロ<フルの順序）でNGの場合GUIにエラーを表示して停止する
- [ ] 成功したキャリブレーションデータをプロファイルに保存できる

**優先度**: P0（必須）

---

#### 3. 学習運転

**ユーザーストーリー**:
実験エンジニアとして、車両の運転特性を取得するために、固定の開度パターンを開ループで走行してログを収集したい

**受け入れ条件**:
- [ ] 開始ボタン押下で、まず停車保持ブレーキ（`stop_brake_opening_pct`）まで踏み込み、車速が 0 に収束するまで待機してから走行前チェックを行う（踏む前に車速が出ていてもブレーキで停止させてから判定する）
- [ ] 走行前チェック（通信・サーボ・キャリブレーション・プロファイル・UPS残量・位置・**車速0**）をすべてパスした場合のみ確認ポップアップを表示する。NG ならエラー表示しブレーキをリリースして終了する
- [ ] 確認ポップアップで「はい」で開始、「いいえ」でブレーキをリリース（原点復帰）して終了する
- [ ] 固定のアクセル・ブレーキ開度パターン（開度スイープ・2%刻みで細かく振る）を開ループで順に走行する。車両プロファイルの最大開度（`max_accel_opening`/`max_brake_opening`）を超える開度は生成しない
- [ ] 停車保持ブレーキを少しずつ緩めた後、アクセル・ブレーキ0%で車速が安定するまで待機してクリープ車速・クリープ加速率を計測する（クリープが出ず0km/hのままなら次の開度振りへ移行）。計測値は学習終了後に車両プロファイルへ反映する
- [ ] 過速度（`max_speed` 超過）・過G（`max_decel_g` 超過、加速・減速とも同一上限）時は非常停止せず、当該パターンの測定を打ち切って次の開度へ進む
- [ ] 過電流・通信断時は非常停止する
- [ ] 実車速・アクセル開度・ブレーキ開度・位置・電流値を100ms周期で連続ログ保存できる
- [ ] 20分以内で完了する

**優先度**: P0（必須）

---

#### 4. 運転モデル学習・PID自動適合

**ユーザーストーリー**:
実験エンジニアとして、精度の高い自動走行のために、収集したログから運転モデルとPIDゲインを学習し、手動調整なしで走行できる状態にしたい

**受け入れ条件**:
- [ ] 学習運転ログまたは過去の走行ログからモデルを学習できる
- [ ] 学習したモデルが車両プロファイルに紐づけて保存される
- [ ] 再学習によってモデルを更新できる
- [ ] モデル学習と同時に、学習ログから PID 初期値（Kp/Ki/Kd）を自動算出してプロファイルへ保存できる（同定できない場合は既存値を保持）
- [ ] 学習結果として MAE・RMSE・R²（加速/減速モデル）と算出 PID 初期値を画面に表示できる
- [ ] モデルと PID 初期値を使って規定パターンを走行し、追従精度（KPI）を最小化するよう PID 最適値へ自動適合できる（PID自動適合）
- [ ] PID自動適合の規定パターンは、車両プロファイルの**最高車速・上限G（`max_decel_g`）を厳守**する
- [ ] 学習運転の正常終了を契機に、①開度パターン走行 → ②モデル作成 → ③PID初期値設定 → ④規定パターン走行でPID最適化、を**自動で一気通貫**実行する
- [ ] PID自動適合の走行中に非常停止が発生した場合は適合を中断する

**優先度**: P0（必須）

---

#### 5. 走行モード管理

**ユーザーストーリー**:
実験エンジニアとして、様々な運転サイクルを実行するために、基準車速CSVをアップロードして管理したい

**受け入れ条件**:
- [ ] 基準車速CSVをアップロードしてモード名を付けて保存できる
- [ ] 走行モード一覧から選択して実行できる

**優先度**: P0（必須）

---

#### 6. 自動運転（走行モード）

**ユーザーストーリー**:
実験エンジニアとして、再現性の高い試験のために、基準車速CSVに従ってアクセル・ブレーキを自動制御したい

**受け入れ条件**:
- [ ] 走行前チェックをすべてパスした場合のみ開始できる
- [ ] 運転モデルと基準車速からフィードフォワード制御用目標位置を50ms周期で算出できる
- [ ] フィードフォワード＋PIDフィードバック制御で実車速を基準車速に追従させられる
- [ ] 基準車速・実車速・アクセル開度・ブレーキ開度をリアルタイムでGUIに表示できる
  - [ ] リアルタイムグラフは現在位置を画面中央に固定（中央固定プレイヘッド）し、現在値を中央の●ポインタで上下表示・波形を左へ流すことで視線追従を容易にする
- [ ] 設定した追従逸脱条件（例：±2.0km/h・4.0s以上）で自動停止できる
- [ ] 走行ログを100ms周期で保存できる
- [ ] 非常停止スイッチ押下で全アクチュエータが即座に原点復帰する

**優先度**: P0（必須）

---

#### 7. 安全システム

**ユーザーストーリー**:
実験エンジニアとして、万が一の際にも安全に停止できるように、非常停止・過電流検知・AC電源断対応が欲しい

**受け入れ条件**:
- [ ] 非常停止スイッチ（室内・操作エリアの2箇所）のいずれかを押すと全アクチュエータが即座に原点復帰する
- [ ] 電流値が閾値を超えた場合に自動停止する
- [ ] AC電源断検知時に安全停止→ログ保存→PostgreSQL正常終了→シャットダウンの順に処理される
- [ ] AC UPSのAC断検知状態をGUIに表示できる

**優先度**: P0（必須）

---

#### 8. 手動操作

**ユーザーストーリー**:
実験エンジニアとして、アクチュエータの動作確認や特定の開度での試験のために、GUIからペダルを手動で操作したい

**受け入れ条件**:
- [ ] 走行前チェックをすべてパスした場合のみ開始できる
- [ ] GUIのスライダーまたは入力フォームでアクセル・ブレーキ開度をリアルタイムで調整できる
- [ ] 操作中のステータスをリアルタイムで確認できる
- [ ] 終了後にログが保存される

**優先度**: P0（必須）

---

#### 9. ログ管理・確認

**ユーザーストーリー**:
実験エンジニアとして、試験結果を分析するために、走行ログをGUIで確認・CSVダウンロードしたい

**受け入れ条件**:
- [ ] 過去3ヶ月分のログをGUIから一覧・グラフ表示できる
- [ ] ログをCSV形式でダウンロードできる
- [ ] 内蔵SSD使用率が80%超の場合に、3ヶ月超のログをCSV+圧縮して外付けUSB SSDに自動アーカイブされる
- [ ] アーカイブ先がストレージの80%超で古いものから自動削除される

**優先度**: P0（必須）

---

#### 10. 起動・初期化

**ユーザーストーリー**:
実験エンジニアとして、安全に作業を開始するために、システム起動時に通信確認と初期化を実施したい

**受け入れ条件**:
- [ ] 電源ONでWeb GUIが自動起動（待機状態）する
- [ ] 起動時に通信（ttyUSB0・ttyUSB1・CAN）を自動確認し、NGはGUIにエラー表示する
- [ ] 「初期化」ボタン押下でアラームリセット→サーボONを実行する
- [ ] 前回正常終了なら原点復帰をスキップ、異常終了・初回なら原点復帰を実施する

**優先度**: P0（必須）

### 拡張機能（Post-MVP）

#### 11. タイムスケジュール

**ユーザーストーリー**:
実験手法開発エンジニアとして、基準車速を使わずに時系列でペダル動作とボタン操作（シフト・エンジンスタート等）を自動化するために、タイムスケジュールを作成・実行したい

**受け入れ条件**:
- [ ] 時刻とアクセル・ブレーキ開度を表形式で入力できる
- [ ] 同一タイムライン上で、時刻を指定してボタンイベント（対象ボタン＋押下時間）を入力できる
- [ ] 対象ボタンはエンジンスタート・シフト（P/N/D）・オプション（合計16個）から選択できる
- [ ] ボタンの押下時間はボタンごとに設定できる（例: エンジンスタート1秒、シフト0.5秒）
- [ ] ループ設定ができる
- [ ] スケジュール名を付けて保存・一覧管理できる

**ハードウェア前提**:
ボタン操作は PCA9685（I2C PWMドライバ）に接続した16個のボタンサーボ（SG90）で物理的にボタンを押下する。押下角度は全チャンネル共通の固定値とし、押下時間のみスケジュールで可変とする。ボタンサーボはアクセル・ブレーキ用アクチュエータ（IAI／Modbus RTU）とは独立したI2Cバスで駆動する。

**優先度**: P1（重要）

## 非機能要件

### パフォーマンス
- **制御周期**: アクチュエータへの位置指令を50ms周期（20Hz）で更新できること
- **ログ記録**: 100ms周期で走行データを記録できること
- **GUI更新**: リアルタイムモニタリングを100ms以下の遅延で表示できること
- **起動時間**: 電源ONからGUI操作可能状態まで60秒以内

### 信頼性
- **連続稼働**: 10時間以上の連続走行が可能なこと
- **データ保全**: ログのPostgreSQL書き込みが正常終了すること
- **異常停止時の安全**: エラー・非常停止・AC断いずれの場合もアクチュエータが原点復帰すること
- **UPS対応**: AC電源断時にAC UPS（1台）からのバッテリー給電中に安全停止シーケンスを実行できること

### ユーザビリティ
- **操作習得**: 説明書なしで走行開始まで操作できること
- **アクセス方法**: ブラウザからIPアドレスを入力するだけで接続できること（アプリインストール不要）
- **エラー通知**: エラー発生時に原因をGUIに表示すること

### セキュリティ
- **ローカルネットワーク限定**: 同一LAN内からのみアクセス可能とする
- **機密情報の非保存**: IDやパスワードなどの機密情報を保存しないこと

### スケーラビリティ
- **ログ容量**: アクティブDBを3ヶ月・アーカイブを外付けSSDで管理し、80%超で自動削除
- **車両プロファイル数**: 複数車両のプロファイルを無制限に管理できること

## スコープ外

明示的にスコープ外とする項目:
- マルチユーザー認証・権限管理
- クラウド連携・リモート（社外）アクセス
- AC UPS 機種選定（電源構成は AC UPS 1 台で 5V・24V 両系統をバックアップする設計で確定。機種選定はTBD）
- 車両のOBD2・CANバスからの車速取得（シャシダイナモCANのみ対応）
- Windows/macOS対応（Raspberry Pi Linux専用）
- グローバル環境へのライブラリインストール
