# 要求内容: タイムスケジュールUIの表形式エディタ刷新

## 概要

タイムスケジュール画面（`.steering/20260701-timeschedule-mode/` で実装済み）の UI を、
JSON テキスト入力から**統合タイムライン表エディタ**へ刷新し、判明している不具合2件を修正する。

## 背景

現行 UI（`src/web/static/js/screens/schedule-sequence.js`）は最小限の暫定版で、
ユーザーから以下の指摘を受けた:

- **名前が入力できない**（不具合）
- スケジュールを JSON コードで書かなければならず分かりづらい → **表形式**で編集したい
- ペダル（Acc/Brk）とボタンが**別々の入力欄**になっている → 1つの統合タイムライン表にしたい
- ボタンはスタートだけでなく **P / N / D / オプション（ch4-15）** も設定できる必要がある

ユーザーの望む編集イメージ（1行 = 1時刻点、ボタンは Push-ON / Push-OFF の状態で表現）:

```
0秒  タイムスケジュールモードスタート
1秒  Acc0%  brk0%  スタートスイッチ Push-ON
2秒  Acc0%  brk0%  スタートスイッチ Push-ON
3秒  Acc10% brk0%  スタートスイッチ Push-OFF
```

→ 1秒でスタートスイッチを押し始め、3秒で離す（押下2.0秒）。3秒で Acc を 10% にする。

**バックエンドは完成済みで変更不要**。CRUD API（一覧/作成/詳細/更新/削除）と
`ScheduleLoop` はそのまま使い、表形式 ⇔ APIモデル（pedal_points + button_events）の
変換はフロントエンドで行う。

## 実装対象の機能

### 1. 不具合修正（真因は調査済み・確定）

- **名前が入力できない**: 共有 `Input`（`sketch.js:292`）は `onChange` に**値文字列**を渡す仕様
  （`onChange={e => onChange(e.target.value)}` 処理済み）だが、schedule-sequence.js は
  `onChange: e => setName(e.target.value)` と**イベント扱い**している。`e.target` が
  undefined → 例外 → controlled input が更新されず入力不能。
- **一覧表示の崩れ**: 共有 `Row`（`sketch.js:320`）は cells に**タプル `[content, width, mono]`**
  を要求する（`c[0]` を描画、`c[1]` を gridTemplateColumns に使用）が、素の文字列/React要素を
  渡している。文字列は先頭1文字だけ描画され（`'名前'[0]`='名'）、React要素（ラジオボタン・
  RowActions）は `[0]` が undefined で何も描画されない。

### 2. 統合タイムライン表エディタ（作成・編集共通）

- 1行 = 1時刻点。列: 時刻[s] / Acc[%] / Brk[%] / ボタン列（トグル）/ 行操作
- ボタン列は既定でスタート(ch0)・P(ch1)・N(ch2)・D(ch3)。オプション1-12（ch4-15）は
  「＋列追加」で必要な列のみ追加
- ボタンセルはクリックで ON ⇔ OFF。ON = その行の時刻から次に OFF になる行の時刻まで押下
- 行の追加（直下に挿入）・削除、総時間の自動表示、ボタン押下区間のプレビュー表示
- JSON テキストエリアは廃止

### 3. 既存スケジュールの編集

- 一覧の行操作に「編集」を追加し、既存スケジュールを表エディタで開いて更新（PUT）できる

## 受け入れ条件

### 不具合修正
- [ ] 新規作成画面で名前・説明が入力できる
- [ ] 一覧に名前・総時間・件数・ループ有無が正しく表示され、ラジオ選択・削除・編集ボタンが機能する

### 表エディタ
- [ ] 表で「1s スタートON / 3s Acc10% スタートOFF」を作成・保存すると、
      `GET /api/v1/schedules/{id}` が
      `button_events=[{time_s:1.0, channel:0, press_duration_s:2.0}]` を返す（生データで確認）
- [ ] P/N/D およびオプション列（ch4-15）のボタンイベントを設定できる
- [ ] 保存前バリデーション（名前必須・時刻昇順・開度0-100・最終行ボタン全OFF）が機能する
- [ ] 既存スケジュールを編集で開くと表が復元され、変更を保存できる

### 回帰
- [ ] `pytest`（762 passed 基準）・`ruff check` が通る（バックエンド無変更の確認）

## 成功指標

- JSON を手書きせずに、ユーザー例のスケジュールを表操作のみで作成できる
- 保存内容が編集で開き直したときに同じ表として復元される（ラウンドトリップ）

## スコープ外

以下はこのフェーズでは実装しません:

- バックエンド変更（models / routers / schemas / schedule_loop / DDL）
- グラフィカルなタイムライン可視化（波形グラフ等）
- 実行中スケジュールの進行位置表示（現在行ハイライト等）
- `SequenceScreen`（シーケンスモード）は Post-MVP プレースホルダのまま
