# 20261103 停車前に基準が 0.5 km/h 未満で這う所で、止まったものとして踏み増す

**状態: 進行中（段0 完了・段1 未着手）**

ゆっくり止まる停車で、基準が 0.1〜0.5 km/h で 0.5〜1.25 秒這います。その間に計画の FF がブレーキを止まった開度（8.09%）より浅く戻し、クリープで +0.4〜0.8 km/h 速すぎになります。L 先の基準が 0.5 km/h を切ったら止まったものとして扱い、停車の長さに応じた開度へゆっくり踏み増す案を試します。根拠は 11-03 の off 3 本（WLTP `drive_log_real_20261103_081809`・UDDS `092319`・US06 `101258`）と、pkl `fwd_model_20261028_220204_hpi2_hold_stop_w_lw.pkl` です。前の案③（ProblemReport_20261103_低速で効いている開度を保つ）は不採用でした。

## 問題

用語:
- **FF** ＝ 計画が前もって決めた開度
- **P（C10）** ＝ 偏差を τ 秒で 0 に戻す量
- **停C** ＝ 停車の手前で P の τ を残り時間に縮める作り
- **停A** ＝ 停車保持の開度を、ブレーキの遅れ L だけ先に指令する作り
- **偏差** ＝ 実車速 − 基準（＋が速すぎ）

- 7.5 km/h 未満の速すぎ（+0.5 超）が、ゆっくり止まる停車で出ます: W 386・444・986、U 957・1187・1244 など
- 案③ は 3 モードとも遅すぎで悪化し、不採用になりました

## 議論で確認した事実

| 項目 | 内容 |
|---|---|
| 速すぎの停車の共通点（off 3 本） | 基準が 0 になる 1 秒前の基準車速（＝最後の 1 秒の減速度）が約 1.2 km/h/s 以下で、基準 0.5 km/h 未満が 0.5〜1.25 秒続きます（W 444: 0.25 km/h・1.25 s・+0.81／W 386: 0.90・0.60 s・+0.55／W 986: 1.10・0.50 s・+0.40／U 957: 0.64・0.80 s・+0.42）。偏差の小さい停車は 1.6〜5.3 km/h/s、0.10〜0.35 s です（U 333・505・1023、US06 41・128 など） |
| その間の計画の FF | 速すぎの停車は、FF の最小が止まった開度 8.09% より浅くなります（W 386 7.50・W 444 7.81・W 986 7.95・U 957 7.92・U 1187 8.01）。偏差の小さい停車は 8.8% 以上です。計画は要る加速度 ≒ 0 なのでブレーキを戻し、クリープが勝ちます |
| 這う基準は守れない | ペダルの生値 1 カウントはロボットの開度で約 0.20%（10-29 `drive_log_real_20261029_042914` とシミュレータの生値を突き合わせ）で、1 km/h 付近では約 1.4 km/h/s にあたります。同じ開度でも生値は ±5 カウント（約 ±1%）ばらつくので、0.1〜0.5 km/h を保つ精度はありません |
| 0.5 km/h 未満で止めたときの偏差 | 車が止まれば、偏差は −基準になります。基準が 0.5 km/h 未満なら、偏差も必ず 0.5 未満です（0.5 は KPI の幅で、車に依存しません） |
| P・DOB・停C（速すぎの停車） | P の実質の強さは偏差 1 km/h あたり 0.9〜1.6% です。1 km/h 付近の効き（約 6.8 km/h/s/%）と合わせると、偏差を返す速さは毎秒 6〜11（1〜1.7 Hz）で、閉ループの −180°（1.1〜1.2 Hz）とほぼ同じです。これより強くすると往復します。停C の τ はゆっくりした停車で 0.72〜0.93 s（ほぼ普段の P と同じ）、速く止まる停車で 0.3〜0.6 s です。DOB は 0.00〜0.10% で、実質働いていません。FF の戻しから速すぎまでが 0.2〜0.4 秒しかないので、FB では間に合いません |
| U 1100 | 停車の手前（基準 1.26 → 0.31）は、P が効いて +0.29 以下でした。+0.52 が出たのは、基準が 0 に触れてすぐ 0.16 km/h/s で上がり始めた後です。発進のブレーキの帯（hold_scene 3）の中で、C10 の P は使われず、保持の PI（Kp 0.135）が −0.02〜−0.07% しか出していません |
| 停車保持と短い停車（コード） | 停車保持 ＝ 止まった開度 8.09% ＋ 10% ＝ 18.09%（`pedal_search.stop_hold_margin_pct`）です。基準 0 が 5 秒以下の短い停車（`launch_short_stop_s`）は、動き出す開度 8.905%（min 4.2 ＋ meta `launch_breakaway_u_pct` 4.705）で待ちます。どちらも基準が 0 になってからの扱いで、停車の手前は今も表の答えで戻しています |
| 止まった開度と動き出す開度の差 | 止まった開度は、動いている車にブレーキを足していき止まった所です。動き出す開度は、止まった車から離していき動き出した所です。実車ではふつう動き出す開度の方が浅くなります。このシミュレータは停車とクリープの境目が読み値 5%（ロボット約 8.45%）の 1 本で向きの区別がないので、差の 0.8% は測り方とペダルのばらつきによるものです（推測。判断の根拠にしない） |
| 動き出す開度で止めておけるか | U 1100 では、8.72〜8.82% で 0.06 km/h まで落ちた車が 0.65 km/h へ動き出しました。止まった開度（8.09%）では止めておけません |

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| 車速と下限の開度を設ける | 基準 1.1 km/h 未満で FF の下限を 8.84%（meta hold_pi）や 8% にする | 不採用（ユーザー）。車速・下限の値の決め方に違和感がある。hold_pi の 8.84% は 0〜3 km/h の往復の平均で、釣り合いの点ではない |
| P・DOB・停C を強くする | 低速の FB を強める | 不採用。P はすでに安定の限界付近で、戻しから速すぎまで 0.2〜0.4 秒しかない。速く止まる停車（τ 0.3〜0.6 s）が往復しやすくなる |
| D3 停車ごとに覚える | 停車ごとに要る開度を学ぶ | 後回し。原因は這う基準（届かない目標）で、覚える値もばらつき（±1%）に埋もれる |
| **基準が 0.5 km/h 未満になったら止まったものとして扱う（採用）** | L 先の基準が 0.5 km/h を切ったら、停車の長さに応じた開度へ、基準が 0 になる時刻までに直線で踏み増す。区間の中の P は踏み増す向きだけ | 採用（ユーザー決定） |

## ユーザー決定（2026-11-03）

- 基準が 0.5 km/h を下回ったら止まったものとして扱い、**ゆっくり踏み増す**
- 始める時刻は **L 先の基準 < 0.5 km/h**（停A と同じ考え）
- 踏み増す先: 長い停車は**停車保持の開度**（止まった開度 ＋ 10%）。短い停車は**動き出す開度**（今の短い停車の待ちと同じ）
- 区間の中では、クリープで動き出さないよう **P は踏み増す向きだけ**
- 止まらずに発進する場面（U 1100 型）も同じ考えで扱う
