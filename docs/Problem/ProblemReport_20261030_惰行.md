# 20261030 短い惰行でペダルを離さず、踏んだまま次のペダルへ渡す（惰行の帯の見直し）

**状態: 進行中（段1 実装中。作業はブランチ `feat/coast-band`・worktree `../driving_robot_coast`）**

ProblemReport_20261029 の ±0.5 の未達で、WLTP の長い 2 件（327 s・620 s）は、計画が「惰行の帯」（要る加速度と惰行の加速度の差が ±0.25 km/h/s 未満なら惰行）でペダルを離したことが原因だった。惰行の行は FB も効かない。案 B（離すときは帯を使わない）と案 D（短い惰行を埋める）を実装し、実機 3 モードで比べる。

## 問題

- 走る前に作る開度の計画（`fwd_plan.build_plan`）は、要る加速度が惰行の加速度に近い（差 < `forward_map.coast_band_kmhs` = 0.25 km/h/s）とき、ペダルを離して惰行にする
- 惰行の行では C10・DOB（偏差を詰める FB）は何もしない。C12（惰行の補助）は、短い惰行だと片足ルールで入れない。そのため 0.8〜1.7 秒の惰行で、偏差が 0.2〜0.4 km/h 積み上がる
- 人が運転するなら、ペダルを離さず、効き始めのすぐ上で踏む量を緩めながら車速を合わせ、次のペダルへ渡す（ユーザー 2026-10-30）

## 議論で確認した事実

| 項目 | 内容 |
|---|---|
| 惰行の帯の規則 | `fwd_plan.py` の `want_accel = need_a − coast_a ≥ coast_band_kmhs`、`want_brake = need_b − coast_b ≤ −coast_band_kmhs`。どちらでもなければ惰行（`FLAG_COAST`）。帯 0.25 は yaml のコメントで「仮値（ユーザー決定 2026-10-03）。フィードバックを入れる段で見直す」とあり、まだ見直していなかった |
| 327 s（WLTP `070530`、23.9 km/h） | 机上で計画を再現（同じ yaml・pkl `fwd_model_20261028_220204.pkl`）した。要る加速度 −0.30、惰行の加速度 −0.54、差 **+0.24**（帯の 0.01 内側）→ 326.0〜327.7 s の 1.7 s を惰行にした。アクセルは 10.99% → 4.2%（min）へ一気に戻った。表で引くと、−0.30 km/h/s に要るアクセルは **10.06%**。偏差は −0.14 → −0.51、最大 −0.58 km/h |
| 620 s（同、45.9 km/h） | ブレーキ 6.3〜6.6% の後、要る加速度 −1.00、惰行の加速度 −0.76、差 **−0.24** → 620.0〜620.8 s の 0.8 s を惰行にした。表で引くと、−1.0 km/h/s に要るブレーキは **6.21%**（効き始め 6.15% のすぐ上。ユーザーの「6.5±0.5%」と同じ所）。偏差は +0.31 → +0.52、最大 +0.57 |
| 惰行の加速度の表は合っていた | 実際の惰行の減速は 327 s で −0.51、620 s で −0.74 km/h/s（表 −0.54・−0.76）。外れたのは「ペダルでなら出せた 0.24 km/h/s を捨てた」分（0.24 × 1.7 s ≒ 0.4、0.24 × 0.8 s ≒ 0.2 km/h） |
| 620.8 s のアクセル 8.25% | 先置き（`FLAG_PREPOS`。効き始め 8.75% − 0.5% に先に置く）で、それ自体は効いていない。その後、基準の減速が −0.5 km/h/s に緩み（惰行 −0.76 より緩い）、計画はアクセル 11.4% を出した。車が速すぎ（+0.55）だったので、C10 が −7.2% 引いて min に戻した |
| 惰行の行で FB が効かない理由 | `deviation_offset_detail` は flag が COAST・STOP・PREPOS の行では何もしない（`fwd_plan.py` 2188 行付近）。C12 は偏差 0.2 km/h で入るが、「次の反対ペダルまでに保持（アクセル 1.49 s／ブレーキ 1.31 s）して戻る時間がない」と入れない。WLTP の「次の戻り待ち」は 9.8 s（`report20261029_RunFF_4.md`）。327 s・620 s がこれに当たったのはコードの規則からの推定（行ごとの理由はログに無い） |
| ペダルの遊び | 効き始めはアクセル 8.75%、ブレーキ 6.15%（pkl meta）。4.2%（min）からその手前までは踏んでも惰行と同じ。「10.6% から緩める」は、実際に効く所では 10.6 → 8.75% の間を使うことになる |
| どれくらい効いているか | 走行中（3 km/h 超）の \|偏差\|>0.5 は WLTP 1.45 s。そのうち 1.10 s は、惰行の最中か終わってから 1 s 以内。0.3〜3 s の惰行で偏差が 0.2 km/h 以上動いた本数: W 7・U 4・H 5・US06 5（`070530`・`073644`・`080034`・`081414`。机上の集計 `scratchpad/coast_plan.py` ほか） |
| 偏差が動いた短い惰行の長さ | 0.45〜1.90 s（上の 21 本）。3 s より長い惰行は C12 の守備範囲 |

## 検討した案

| 案 | 内容 | 判断 |
|---|---|---|
| A. 帯を狭める（0.25 → 0.05 など） | 惰行にするのを、差がほぼ 0 のときだけにする | 不採用。入るときにも効くので、効き始めのあたりでペダルを出し入れする回数（KPI ③）が増えやすい |
| **B. 離すときは帯を使わない（採用）** | 踏み始めは今の帯 0.25 のまま。いま踏んでいるペダルは、要る加速度が惰行の加速度を越える（差の符号が変わる）まで踏み続け、そこで離す／反対のペダルへ渡す。その行は惰行ではないので C10・DOB が効く | 採用（ユーザー 2026-10-30） |
| C. C12（惰行の補助）を緩める | 短い惰行でも、直前と同じペダルなら補助に入れる | 不採用。偏差が 0.2 km/h に積み上がってから入る後追いになる |
| **D. 短い惰行を埋める（採用。B と組み合わせも比べる）** | 計画の惰行の区間が X 秒より短いとき、惰行をやめてペダルで埋める。前後が同じペダルならそのペダルで、差がそのペダルの向きにない行は効き始めで保つ。前後が違うペダルなら、差の符号に合う側のペダル | 採用（ユーザー 2026-10-30。B 単独・D 単独・B+D を比べる） |

## 各段の内容

### 段1: 案 B（離すときは帯を使わない）

**内容**

- `tests/research/fwd_plan.py` の `build_plan` で `want_accel`・`want_brake` を決めた所に、時刻順の判定を足す（`coast_band_release_at_zero=True` のときだけ）
  - 入る: 今と同じ（差 ≥ +帯でアクセル、≤ −帯でブレーキ）
  - 続ける: 前の行がアクセルなら、差 > 0 かつ `u_a > 0` の間はアクセルのまま。前の行がブレーキなら、差 < 0 かつ `u_b < 0` の間はブレーキのまま
  - 差の符号が変わったら離す。反対側の帯を越えていれば、その行から反対のペダル（先置き・すき間の処理は今までどおり後段で掛かる）
- 開度は今と同じく表を逆に引く（差が小さい行は効き始めのすぐ上になる）。flag はその行で引いた種類（実測・穴埋め・範囲外）のまま。FB（C10・DOB）は今の規則のまま効く
- 低速の表の側（dir 規則の `_launch_midway` など）は、今の「入る」判定で決めたものを使う（側の決め方は変えない）。停車保持（`FLAG_STOP`）は今までどおり後で上書き
- `tests/research/config.py` の `ForwardMapSection` に `coast_band_release_at_zero: bool = False` を足し、`mode_drive.forward_map_plan_args` から渡す。本体 yaml にはキーとコメントだけ書き、値は false（採否は段5）

**調整値**

| 値 | 現在 | データの根拠 | 何に効くか | いつ決めるか |
|---|---|---|---|---|
| 離すしきい値（差 0） | 0 km/h/s（固定。キーにしない） | 規則から決まる値: 差が 0 ＝ 惰行で要る加速度がちょうど出る所。そこより先ではペダルが逆向きに効く | ペダルを離す時刻 | 決め直さない |
| `coast_band_kmhs`（入る帯） | 0.25 | 仮の値（2026-10-03）。今回は入る側にだけ使う | 惰行から踏み始める時刻・ペダルの出し入れの回数 | 段5 の結果でペダルの往復が増えなければ据え置き |

**確認**

- `ruff check tests/research`、`test_research_fwd_plan.py`（新しい関数のテスト: 帯の内側でも前のペダルが続く・差の符号が変わると離す・既定 false で出力が今と同じ）、`test_research_config.py`（新キーは既定値だけ）

### 段2: 案 D（短い惰行を埋める）

**内容**

- `build_plan` で惰行／ペダルの判定の後（停車保持の上書きの後、先置き・すき間の処理の前）に、惰行の区間を探して、長さ < `coast_fill_max_s` の区間を埋める（`coast_fill_max_s > 0` のときだけ）
  - 前後が同じペダル: そのペダルで埋める。差がそのペダルの向きにある行は表を逆に引いた開度、向きにない行は効き始めの開度（min ＋ meta の `*_onset_u_pct`）で保つ
  - 前後が違うペダル: 差の符号に合う側のペダルで埋める（差 > 0 ならアクセル、< 0 ならブレーキ。向きにない行は効き始めで保つ）
  - 区間の片側が停車保持・モードの端のものは埋めない
- 埋めた行の flag は新しく `FLAG_COAST_FILL = 6`（ラベル「惰行の埋め」）にし、FB（C10・DOB）は効く（`deviation_offset_detail` の除外に入れない）。C12 は `FLAG_COAST` の行だけなので、埋めた行には入らない
- 設定は `ForwardMapSection.coast_fill_max_s: float = 0.0`（0 ＝ 無効）。yaml はキーとコメントだけで値は 0

**調整値**

| 値 | 現在 | データの根拠 | 何に効くか | いつ決めるか |
|---|---|---|---|---|
| `coast_fill_max_s` | 0（無効）。実機は 2.0 で走る | 半分データ由来: 偏差が 0.2 km/h 以上動いた短い惰行は 0.45〜1.90 s（10-29 の 4 モード 21 本）、ユーザーの見立ては 0.8〜1.7 s。2.0 はそれを覆う切りのいい値で、根拠は弱い | 埋める惰行の長さの上限。長いと惰行がほぼ無くなり、ペダルの往復が増えやすい | 段5。埋めた区間の偏差と往復の回数を見て決め直す |

**確認**

- `ruff check`、`test_research_fwd_plan.py`（同じペダルで埋める・違うペダルは差の符号で分ける・停車保持に接する区間は埋めない・既定 0 で出力が今と同じ）、`test_research_config.py`

### 段4: 実機 3 通り × 3 モード

**内容**

- 本体 yaml から `runs/s30c_<案>_<mode>.yaml` を作る（本体との違いは `wltp_mode_name` と `coast_band_release_at_zero`・`coast_fill_max_s` だけ・diff で確認）。`chmod a-w` し md5 を `scratchpad/s30c.md5` に控える（`run-yaml-copies-can-be-overwritten`）
- 今の値は 10-29 の `070530`（WLTP）・`073644`（UDDS）・`081414`（US06）。同じ pkl・同じシミュレータ（10-29 の跳びの修正の後）なので走り直さない

**実行手順**（Claude が実行）

```bash

  .venv/bin/python -m tests.research.main --steps 1,3 --hw real --config tests/research/results/analysis/runs/s30c_${v}_$m.yaml; echo "$v $m exit=$?"

```

### 段5: 比較と採否
