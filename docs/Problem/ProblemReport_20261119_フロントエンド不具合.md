# 20261119 WebUI（フロントエンド）の不具合を洗い出す

**状態: 進行中（段4・4b スタブ確認済み。ユーザーの確認と実機の確認待ち）**

非常停止の実機確認（RPD_Phase_20261119_EmergencyStop）の途中で、WebUI の「自動運転」画面に不具合が 2 つ見つかった。
(A) 走行前（準備・走行前チェック）なのに、時間軸と経過時間が進む。モードが本当に始まると 0 秒に戻る。
(B) 画面を通さずに始めた走行を開くと、「走行モードを選択してください」が出て、基準車速の線が引かれない。
まだ直していない（フロントエンドの変更はユーザーの承認後に行う）。
続けて同じ日に、ユーザー（8080）と Claude（8081）が別々のスタブのサーバーで全画面を見て、不具合を「## 不具合一覧」に足していく（ハード未接続）。
Claude の 1 周目（全 11 画面＋非常停止の画面）で A' と C〜T の 18 件を追加した。高は A'・G・M・Q（固定の見本の文が実際の状態のように出る・ペダル位置の表示ずれ・確認なしの削除）。

## 問題

- **(A) 準備中に時間軸が進む**（ユーザー報告 2026-11-19 07:30）
  - 画面から 04_WLTP_Mid を開始すると、状態が「準備中」のうちに「経過 00:23/07:13」まで進む。
  - グラフの時間軸も 10〜35 秒まで流れ、基準車速の線は 50 km/h 付近まで先へ進む。このとき実車速は 0.0 km/h、ペダルは 0%。
  - モードが始まる（Ready・D を押して時刻 0 になる）と、0 秒に戻って正しい表示になる。
  - 困ること: 準備中の画面が「走行が始まって遅れている」ように見える。非常停止などの判断を誤らせるおそれがある。
- **(B) 画面を通さずに始めた走行が、モードなしに見える**（2026-11-19 07:25、Claude が API から開始したとき）
  - 走行中なのに「走行モード・スケジュール・シーケンスを選択してください」の窓が出る。
  - 上部の表示は「車: —　走行モード: —」になり、基準車速の線が引かれない。
  - 実車速・下の欄の「基準 40.4」（ランナーからのサンプル）は正しく出ている。
  - 困ること: 別のブラウザ・別の端末で開いたときや再読み込みしたときに、いま走っているモードが画面で分からない（推測。開いたブラウザで画面上の選択が無い点は同じため）。

## 議論で確認した事実

| 項目 | 内容 |
|---|---|
| (A) 出たときの状態 | 画面「状態 準備中・経過 00:23/07:13・実車速 0.0 km/h・アクセル 0.0%／ブレーキ 0.0%」（ユーザーのスクショ 07:30）。ランナーの状態は prepare → pre_check → step 24（モニタ 07:29:57・07:30:30） |
| (A) 時間軸の起点の決め方 | `src/web/static/js/screens/auto-drive.js` 101〜112 行。`mode_time_s ?? t_s` で起点を置き直す。`t_s` はランナーが始まってからの秒 |
| (A) 原因（推測・コードから） | 準備・走行前チェックの間は、サンプルの `mode_time_s` が null。そのため `t_s`（走行前チェックからの秒）が起点に使われ、時間軸が進む。モードが始まると `mode_time_s` が 0 に飛び、300ms 以上ずれるので起点を置き直し、0 秒に戻る。`t_s` に頼るのは学習運転・スケジュール用（コメントどおり）で、モード走行には当てはまらない |
| (A) 再現した走行 | セッション 490c5f84（`drive_log_real_20261119_073028.csv`、DB 取り込み済み）。モード時刻 0 は走行開始から約 33.5 s（「[手順 24] 0 秒: Ready」） |
| (B) 出た条件 | `POST /api/v1/drive/start` を直接呼んで開始（job4、セッション 41e5c0ae）。画面のモードの選択は画面の中の状態で、走っているジョブの `mode_id`・`mode_name` から引き直していない（推測。`auto-drive.js` 633 行の `no_mode` の窓の条件はまだ読んでいない） |
| (B) 画面から開始したとき | 正常。上部に「走行モード: 04_WLTP_Mid」、基準車速の線も出る（ユーザーのスクショ 07:29） |
