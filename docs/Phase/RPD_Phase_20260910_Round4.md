## 0. 目的

第3ラウンドで **p95 は 2.92 → 1.42（−51%）** まで改善したが、
**最大逸脱（PRD: 全走行区間で 1.0km/h を超えないこと・例外なし）は ILC 13 反復を通じて
3.82〜5.19km/h で横ばい＝改善ゼロ**だった。p95 と同格の Must なので、本ラウンドは
**最大逸脱を主目的**に置き、ILC の操作対象の外（プラン生成のタイミング設計・
ブレーキ不感帯の扱い・FB 権限・採否基準）を変える。

スコープ（ユーザー確定）: 優先 A+B+C+D ＋ 制御フロー.md の要因②（FB 権限）。
実機/ベンチは B-1（不感帯再測）と E-1（ペダル無操作の定常記録）。
優先 F（本番モードのプラン・`refine_final_runs`・S 字モーション・ボーレート・
滑らかさ KPI・PCON-CB No.152）と KPI 閾値の再交渉は対象外。

### Phase 2: 優先A — 前倒しを向き別にする

| # | 内容 | 判断根拠 |
|---|---|---|
| A-1 | 走行時のプラン参照を **①折返し点への距離で前倒しを線形に絞り（`_plan_lead_at`）、②同じ向きの中では「より踏んでいる側」を採る**（`_plan_at`）方式へ | 閉ループ模擬で **max 5.91 → 5.68、違反時間 67.7 → 53.9s（−20%）**。p95 は 3.10 → 3.20 と微増 |
| A-3 | ILC のリード **Δ = θ + 0.5s → Δ = θ**（`PLAN_LEAD_RESPONSE_S` 0.5 → 0.0） | `replay_plan_update --all-cycles` の 26 ペアで Δ=θ が **18 勝 8 敗**。追加リードを 0.25/0.5/1.0/1.5s と増やすほど単調に悪化（18→18→20→22） |
| A-4 | ILC 候補の Q カットオフ **0.2 → 0.5Hz**（`PLAN_UPDATE_CUTOFF_HZ`） | 実機 `5ac4f31d` の頂点区間で候補プランを作り直し、踏み増し量が **+3.01 → +3.98%**（+32%）。1.0Hz は +4.10% と頭打ちで高周波が増えるため 0.5 を採用 |
| A-2 | `required_accel` の窓中心 `center_ratio` を可変化。**既定は 1.0（センタリング）に据え置き** | 掃引で center を後方窓へ寄せるほど p95・max とも単調悪化（1.00: p95 3.21/max 5.70 → 0.00: 3.84/5.85）。**当初の見立ては否定された** |
| A-5 | `PLAN_DELTA_LIMIT_PCT` は **8.0 のまま据え置き** | 頂点で Δlimit を 8/12/15% と振っても踏み増し量は +3.98 → +4.00 → +4.00% でほぼ不変。**「±8% が binding」（引き継ぎ ⑤-b）は実測で否定された** |

**実装上の要点**: 前倒しの絞り込みは**連続**でなければならない。
「符号が変わったら前倒しをやめる」という二値の切り替えを最初に実装したところ、プラン
effort が 0 を跨ぐ瞬間に指令が数 % 跳び、閉ループ模擬で開度変化率 RMS が 7.9 → 12.5 %/s に
悪化した（ペダルが「パチン」と動く挙動そのもの）。折返し点までの距離による線形の絞り込みへ
置き換えて解消した。

### Phase 3: 要因② — FB 権限の向き判定

`_is_accel_side` の判定を **基準速度のトレンド → 今動いているペダル（直前サイクルの
合成 effort の符号）** へ変更（不感帯 0.5%、初回は従来どおりトレンドでシード）。

ロバスト上限 `Kc = 1/(k'(v)·(θ+τc))` の `k'` は「これから動かすペダルのゲイン」でなければ
安定余裕の見積りにならない。旧実装では減速区間で常に制動側（Kc 0.27〜0.36）が選ばれ、
プランが惰行でアクセルを当てている局面でも FB がほぼ効かなかった。

**途中で 1 度誤った**: 最初は「偏差の符号」で決めたが、閉ループ模擬で **max が 5.91 → 6.71 と
悪化**した。プランが強く制動している最中でも駆動側の小さい `k'` を選んでしまい、実際に動く
ブレーキペダルに対して安定余裕を過大評価するため。ペダル側の判定に直して
**max 5.91（据え置き）・違反時間 67.7 → 57.0s（−16%）** となった。

### Phase 4: 優先B — ブレーキ不感帯 5% の扱い

| # | 内容 |

### 期待値についての注意

閉ループ模擬が示した A+② の効果は **max −3.9%・違反時間 −20%** であり、
引き継ぎ資料の見積り「A を潰せば max 4.06 → 約 2.5」には届いていない。理由は、
走行時の前倒し（0.2〜0.42s）は**約 2.5 秒の前倒し合計のうちの一部でしかない**こと。
残りは基準プラン自身が持つ非因果平滑（`required_accel` のセンタリング窓 ±0.5s と
`zero_phase_lowpass` 1.0Hz）で、A-2 の掃引ではそこを因果側へ寄せると**かえって悪化**した。

なお、引き継ぎ資料が前倒し合計に数えている「ILC リード Δ=1.55s」は、
プラン波形を時間方向へずらすものではなく**どの誤差をどの時刻の指令に帰属させるか**を
決める量なので、性質が違う。過剰分（+0.5s）は A-3 で実測に基づいて外した。

## 5. ユーザー実施事項

### B-1: ブレーキ不感帯の機械的再測（**実機モード**・ユーザーが起動）

> **訂正（2026-09-10）**: 本節は当初「ベンチモードで実施」と書いていたが**誤り**。
> ベンチモード（`DRIVING_ROBOT_BENCH_GPIO_ONLY=1`）は `factory.py:93-104` で
> アクチュエータを `_StubActuator` に差し替えるため、**ロッドは物理的に動かない**。
> ペダル接触点の実測には実機モード（`DRIVING_ROBOT_USE_REAL_HW=1` のみ）が要る。

同定値 5.0% が (a) ペダル／リンクの機械的な遊び（実在する物理量）か、
(b) `calibration_data` のゼロ点がペダル接触前に置かれている誤差か、を切り分ける。

**換算**（プロファイル `000_sample` の現行キャリブレーション、位置の単位は 0.01mm）:

```
brake_zero_pos = 633 (6.33mm)   brake_full_pos = 5872 (58.72mm)   stroke = 5239 (52.39mm)
opening_to_position(x%) = 633 + round(5239 * x / 100)
  → 開度 1.0% = 52 units = 0.524 mm
  → 開度 0.5% = 26 units = 0.262 mm  ← 1 ステップ
  → 開度 5.0% = 262 units = 2.62 mm  ← 同定された不感帯の物理量
```

つまり検証したい主張は「**ブレーキロッドが 2.62mm 動くまで制動が始まらない**」。

**使う経路は MANUAL（`/manual/*`）。CALIBRATING（`/calib/*`）は使わない。**
`jog_axis` は READY から呼ぶと CALIBRATING へ自動遷移し（`robot_controller.py:1924-1927`）、
CALIBRATING の出口は READY か EMERGENCY だけ（`:116`）。READY へ戻るには
`save_manual_calibration` が要り、しかもゼロ/フル 4 点すべてが未設定だと失敗して
CALIBRATING に留まる（`calibration.py:139-143`）＝**現行の校正値を上書きしないと抜けられない
状態にはまる**。MANUAL なら `stop_manual` で READY へ戻り、校正値には一切触れない。

**手順**:

1. ユーザーが実機モードでアプリを起動し、初期化して READY にする。
   車両は停止・輪止め。エンジンは OFF でよい（倍力が効かないだけで接触点は測れる）。
2. `POST /api/v1/drive/manual/start` で MANUAL に入る。
3. `POST /api/v1/drive/manual/home {"axis":"brake"}` で原点復帰。
   MANUAL のジョグは校正範囲 `[633, 5872]` にクランプされる（`:1944-1954`）ので、
   最初のジョグで 633（＝開度 0%）に着く。
4. `POST /api/v1/drive/manual/jog {"axis":"brake","step":26}` を繰り返す（1 回 = 0.5%）。
   各ステップで次の 3 つを記録する:
   - **目視**: ロッド先端がペダルに触れたか
   - **モータ電流**: WebSocket `/ws` の `brake_current_ma`（無負荷ベースラインからの立ち上がり）
   - **触感**: ペダルを手で軽く揺すって遊びが残っているか
   レスポンスの `position` が実位置なので、`(position − 633) / 5239 × 100` が開度 [%]。
5. `POST /api/v1/drive/manual/stop` で終了（両軸が原点復帰しペダルを解放する）。

| 位置 | 633 | 659 | 685 | 712 | 738 | 764 | 790 | 816 | 843 | 869 | 895 |
|---|---|---|---|---|---|---|---|---|---|---|---|
| 開度 [%] | 0.0 | 0.5 | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 | 3.5 | 4.0 | 4.5 | **5.0** |
| ロッド変位 [mm] | 0.00 | 0.26 | 0.52 | 0.79 | 1.05 | 1.31 | 1.57 | 1.83 | 2.10 | 2.36 | **2.62** |

**判定**:

| 接触開度 | 意味 | 次の手 |
|---|---|---|
| ≈ 0% | ゼロ点は接触点にある。5% は**ペダル側の遊び＋液圧の立ち上がり**＝実在する物理量 | 優先B の設計変更（B-2/B-3）をそのまま実機評価 |
| ≈ 5% | ゼロ点がペダルから 2.6mm 離れている＝**校正の誤差** | `brake_zero_pos` を接触点へ再設定して再キャリブレーション＋再同定。不感帯そのものが消える可能性がある（最も筋が良い） |
| 2〜3% | 両方の寄与 | 校正を詰めたうえで残る不感帯に対して B-2/B-3 |

値が下がれば `brake_deadband_pct` のプロファイル更新だけで 5 経路すべてに反映される。
